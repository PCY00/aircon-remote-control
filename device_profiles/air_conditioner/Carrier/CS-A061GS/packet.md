# Carrier CS-A061GS IR 패킷

## 상태

- 프로필 상태: `experimental`
- 리모컨 식별자: `remote-16214-15597`
- 에어컨 모델: 사용자가 `Carrier CS-A061GS`로 확인
- 실제 IR 송신: Pi GPIO18·P2N2222A·5V IR 모듈로 `power_off` 실전송 및 에어컨 반응 확인
- 반송파: 판매자 자료는 38kHz라고 안내하지만 아직 계측하지 않음

프로그램은 이 문서를 해석하지 않는다. 실행 데이터는 `commands.json`이 기준이며 이
문서는 측정 근거와 주의점을 사람이 검토하기 위해 유지한다.

## 공통 프레임

- 관측 프레임 길이: 48비트, 6바이트
- 대부분 한 버튼 입력에서 동일 프레임 2회
- 일반 상태 프레임의 바이트는 두 개씩 비트 보수 관계
- 대표 시작부: 약 4.35ms pulse / 4.35ms space
- 대표 데이터 pulse: 약 560µs
- 대표 0/1 space: 약 520µs / 1.61ms
- 프레임 종료: 마지막 데이터 space 뒤 약 560µs stop pulse
- 반복 프레임 사이: stop pulse 뒤 약 5.15ms space

Step 4 송신기는 위 대표값으로 `ir-ctl` pulse/space 파일을 생성한다. 전원 OFF 생성 파형의
mark/space 분류와 반복 구조가 원본 `power-off-from-cool-17-high-01.ir`과 동일함을 자동
테스트로 확인했다. Pi에서 `/dev/lirc0` raw 송신과 실제 에어컨의 전원 반응도 확인했다.
다만 반송파와 광출력 세기를 계측기로 측정한 것은 아니며, 성공 거리의 정확한 수치도 아직
측정하지 않았다.

## 냉방 상태 생성 규칙

```text
b2 4d [풍량] [온도]
```

풍량 바이트쌍:

| 풍량 | 바이트 |
|---|---|
| 자동 | `bf 40` |
| 약 | `9f 60` |
| 중 | `5f a0` |
| 강 | `3f c0` |

온도는 17℃를 0으로 한 값을 Gray code로 바꾸고 5번째 바이트의 상위 니블에 넣는다.
6번째 바이트는 그 보수다. 17–20℃에서 실측으로 규칙을 검증했으며 21–30℃는 설명서의
지원 범위와 이 규칙으로 생성하지만 아직 온도별로 캡처하지 않았다.

## 명시 명령

| 명령 | 프레임 | 성격 |
|---|---|---|
| 전원 OFF | `b2 4d 7b 84 e0 1f` ×2 | 명시 상태 |
| 자동 | `b2 4d 1f e0 08 f7` ×2 | 상태 |
| 제습 | `b2 4d 1f e0 04 fb` ×2 | 상태 |
| 송풍 | `b2 4d 3f c0 e4 1b` ×2 | 상태 |
| 쾌속냉방 | `b5 4a f5 0a a2 5d` ×2 | 즉시 명령 |
| LED | `b5 4a f5 0a a5 5a` ×2 | 토글 후보 |
| 풍향고정 | `b2 4d 0f f0 e0 1f` ×1 | 즉시 명령 |
| 풍향선택 | `b2 4d 6b 94 e0 1f` ×2 | 본체 상태 기반 토글 |

경제운전 첫 입력은 특수 프레임 한 번 뒤 냉방 17℃ 자동풍량 상태 프레임 두 번이 이어지는
3프레임 메시지다. 이 명령은 캡처 당시 상태에 종속될 가능성이 있어 실제 송신 단계에서
별도로 확인한다.

## 원본 근거

원시 캡처와 메타데이터의 기준본은 저장소 루트의
`signals/remote-16214-15597/`에 있다. 중복 복사로 두 기준본이 생기는 것을 피하기 위해
이 프로필의 `captures/README.md`가 해당 경로와 명령별 캡처 ID를 연결한다.

전체 측정 과정은 `docs/hardware/remote-control.md`를 참고한다.
