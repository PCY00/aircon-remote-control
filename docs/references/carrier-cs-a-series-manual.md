# Carrier CS-A Series 사용·설치 설명서 확인 기록

## 출처와 범위

- 사용자 제공 파일: `Carrier CS-A061GS Air Conditioner.pdf`
- 문서 표기: Carrier CS-A Series, `P/N: 42CMH75401G-R`
- PDF 전체: 32쪽
- 리모컨 관련 확인 범위: PDF 21–26쪽, 인쇄면 18–23쪽

이 설명서는 CS-A061/A062/A081/A082/A101/A102 계열을 함께 다룬다. 파일명만으로 현재 실물 에어컨의 정확한 세부 모델까지 확정하지 않는다.

## 리모컨 기본 규칙

- 운전선택 순환: 자동 → 냉방 → 제습 → 송풍
- 풍량 순환: 약 → 중 → 강 → 자동
- 희망온도 범위: 17–30℃, 1℃ 단위
- 풍향선택: 첫 입력에서 상하 조절판 연속 이동, 다시 누르면 현재 위치 정지
- 경제운전: 운전정지 중 경제운전을 누르며, 일반 운전 복귀는 운전선택으로 다른 모드를 선택
- LED와 쾌속냉방은 버튼 위치만 표시되고 동작 설명은 해당 리모컨 페이지에 없다.

따라서 실물에서 풍량 화살표가 사라진 상태는 매뉴얼의 `자동` 풍량으로 확정할 수 있다. 사용자에게 확인받은 풍향선택의 스윙 시작·정지 동작도 매뉴얼과 일치한다.

## 타이머 운전

리모컨의 외장 버튼 이름과 매뉴얼상의 의미를 다음처럼 대응한다.

| 외장 버튼 | 매뉴얼상 기능 |
|---|---|
| 예약선택 | TIMER ON, 켜짐 예약 시간 설정 |
| 예약취소 | TIMER OFF, 꺼짐 예약 시간 설정 |

켜짐·꺼짐 예약 모두 같은 시간 증가 규칙을 사용한다.

- 첫 입력: `0.0h` 표시
- 0.5–10시간: 누를 때마다 0.5시간 증가
- 10시간 이후–24시간: 누를 때마다 1시간 증가
- `24h` 다음: `0.0h`로 복귀하며 해당 예약 취소
- 켜짐과 꺼짐 예약을 동시에 설정할 수 있으며 이때 `TIMER ON`, `OFF`가 함께 표시됨

사용자의 실물 관찰도 이 규칙과 일치했다. `0.0h`에서 입력을 멈추면 약 1초 뒤 편집 표시가 사라졌고 예약이 남지 않았다. 0.0h가 아닌 값에서 멈추면 해당 TIMER 표시가 유지됐다.

## 예약 신호 구조의 실측

예약 시간 버튼을 누르는 동안에는 IR이 나오지 않는다. 0.0h가 아닌 값에서 입력을 멈추고 약 1초가 지나 TIMER 표시가 확정될 때 예약 패킷을 한 번 전송한다.

통제된 60초 원샷 수신에서 TIMER ON 1.0h 상태를 1.5h로 올리고 기다렸더니 `b2 4d 3f c0 03 05`가 동일한 두 프레임으로 수신됐다. 5번째 바이트 `03`은 0.5시간 단위의 세 단계와 일치한다. 마지막 `03 05`는 일반 상태 패킷의 보수쌍이 아니므로 예약 시간과 종류를 위한 별도 구조다.

앞선 12초 무신호 시험은 SSH 명령이 사용자에게 안내되기 전에 약 10초를 사용해 실제 조작 시점에는 관측창이 거의 끝난 잘못된 실험이었다. 이 결과는 저장하지 않았고 예약 무신호의 근거에서도 제외한다.

매뉴얼은 설정 시 리모컨을 본체로 향하게 하라고 안내하므로 예약 시간은 커밋 패킷으로 본체에 전달되는 것으로 보는 것이 자연스럽다. 미수신 시 약 15분 지연된다는 설명이 재송신을 뜻하는지 등은 아직 확인하지 않았다.

## Raspberry Pi 구현 결정

웹 UI에서는 리모컨의 0.0–24h 입력 방식과 예약 패킷을 모두 재현할 수 있다. 다만 기본 예약 실행은 Raspberry Pi가 담당하도록 설계한다.

- 켜짐 예약: 서버가 지정 시각에 원하는 운전 상태 패킷 전송
- 꺼짐 예약: 서버가 지정 시각에 명시적 OFF 패킷 전송
- 재부팅 복구: 예약 정보를 영속 저장하고 서비스 시작 시 다시 불러옴
- 안전: 동일 예약의 중복 실행 방지와 실행 결과 로그 기록

이 방식은 본체 내장 타이머의 상태를 외부에서 확인하기 어려운 문제를 피하고 Tailscale 웹 UI에서 절대시각·지연시간 예약을 모두 제공할 수 있다. TIMER ON 1.5h 원시 패킷은 연구 자료로 보존하지만 추가 예약 패킷 해독은 필수 범위에서 제외한다.
