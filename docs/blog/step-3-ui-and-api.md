# Step 3 — Room First UI 구성과 IR 코드 연결

> Step 2에서 얻은 Carrier 패킷을 화면 버튼에 직접 박아 넣지 않고, 공간·기기·장면을 중심으로
> 한 반응형 스마트홈 UI와 의미 기반 API로 연결한 과정이다. 이 단계의 하드웨어 출력은 Mock이며,
> 실제 IR 송신은 Step 4에서 활성화한다.

## 1. 에어컨 리모컨 화면이 아니라 스마트홈의 시작점

에어컨 하나만 생각하면 전원과 온도 버튼만 있는 화면으로 충분하다. 하지만 앞으로 조명, TV,
센서, ESP32-H2 기반 Zigbee 노드까지 추가할 계획이었다. 그래서 첫 화면의 중심을 제품 종류가
아닌 **공간**으로 정했다.

```text
홈
├─ 빠른 장면: 집에서 · 외출 · 취침
├─ 공간: 전체 · 거실 · 침실 · 사용자가 만든 공간
└─ 공간 안의 기기 카드
```

원룸에서는 거실과 침실이 같은 공간일 수 있고, 큰집에서는 부엌이나 서재가 더 필요하다.
공간의 이름, 추가·삭제와 정렬을 사용자가 정할 수 있게 한 이유다. 공간 탭은 `전체`가 먼저
오고 그다음 사용자 공간이 배치된다.

빠른 장면도 고정 버튼이 아니다. 여러 기기의 명령을 묶어 한 번에 실행하는 사용자 정의
동작이다. 예를 들어 `외출`은 에어컨과 조명을 끄고, `취침`은 에어컨을 냉방 26℃ 약풍으로
설정하는 식이다.

## 2. Room First 디자인 결정

여러 대시보드 시안을 비교한 뒤 A 타입인 Room First를 선택했다. 디자인 기준은 다음과 같다.

- 모바일에서는 설치형 앱처럼 한 손으로 조작할 수 있는 하단 내비게이션
- 데스크톱에서는 넓이를 활용하는 좌측 사이드바와 카드 그리드
- 밝은 아이보리 배경과 파란 제어색, 동작 상태를 나타내는 초록색
- 라이트·다크 테마 모두 제공
- 홈, 기기, 자동화, 더보기의 정보 구조는 화면 크기가 바뀌어도 유지

모바일과 PC가 별도 앱이 아니라 하나의 반응형 웹이므로 같은 Tailscale 주소의 포트 `8001`을
사용한다.

운영 화면에서는 초기 디자인 선택용이던 `따뜻한 A · 장면 먼저` 배지와 상단 테마·화면
도구 모음을 제거했다. 테마와 화면 구성은 `더보기`에 모으고 `자동·휴대폰·PC` 중 하나를
고를 수 있게 했다. PC 모드는 최대 1920×1080을 기준으로 좌측 내비게이션과 2열 홈을 쓰며,
작은 화면에서는 자동으로 휴대폰 레이아웃을 사용한다.

## 3. 기기 추가 흐름

기기를 등록할 때 단순히 이름만 받지 않고 실제 제어 프로필을 선택하게 했다.

```text
1. 기기 종류
   에어컨 / 조명 / TV / 기타
2. 연결 방식과 브랜드·모델
3. 표시 이름·공간·아이콘
4. 등록
```

현재 실제 지원 모델은 다음 하나다.

```text
에어컨 → Carrier → CS-A061GS
```

지원 목록에 없는 모델은 `새 모델 요청`으로 보낸다. 정확한 브랜드와 모델명, 제품 사진은
필수이고 리모컨 사진과 매뉴얼은 선택 첨부다. 사용자 업로드는 코드 배포 때 사라지지 않도록
프로필 기준본과 Pi 런타임 데이터 폴더를 분리했다.

```text
device_profiles/    검증된 모델과 명령, 로컬 기준본
device_requests/    사용자가 올린 미지원 모델 자료, Pi 영구 데이터
```

지원 모델 하나의 내부 구조는 다음과 같다.

```text
device_profiles/air_conditioner/Carrier/CS-A061GS/
├─ profile.json     모델·기능·전송 방식
├─ packet.md        사람이 읽는 분석 기록
├─ commands.json    프로그램이 읽는 패킷 데이터
├─ captures/        원시 IR 캡처
└─ assets/          제품·리모컨 사진과 매뉴얼
```

## 4. UI가 패킷을 몰라도 되는 API

프런트엔드가 `b2 4d ...` 같은 바이트를 알고 있으면 모델이 추가될 때마다 화면 코드도
바뀐다. UI는 사용자의 의도만 보내고 백엔드가 등록 기기와 모델 프로필을 찾아 패킷을 선택하게
했다.

```text
UI
  ↓ power_off / cool 24℃ / fan high
의미 기반 API
  ↓ 등록된 기기와 모델 조회
Carrier CS-A061GS 프로필
  ↓ commands.json에서 프레임 선택·생성
전송 어댑터(Mock 또는 실제 IR)
```

주요 API는 다음과 같다.

| API | 역할 |
|---|---|
| `GET /api/v1/device-profiles` | 지원 모델과 기능 조회 |
| `POST /api/v1/devices` | 이름·공간·아이콘·모델로 기기 등록 |
| `GET /api/v1/devices` | 등록 기기와 마지막 요청 상태 조회 |
| `POST /api/v1/devices/{id}/commands` | 의미 기반 명령 실행 |
| `GET /api/v1/ir/transmitter` | 현재 IR 전송 계층 상태 확인 |

서버가 기억하는 값은 에어컨에서 되돌려 받은 실제 상태가 아니라 마지막으로 요청한
`last_desired_state`다. 적외선은 단방향이므로 다른 리모컨으로 에어컨을 조작하면 두 상태가
달라질 수 있다는 한계를 API와 UI에서 구분했다.

## 5. 에어컨 제어 패널

Carrier 기기 카드를 선택하면 다음 기능을 제어할 수 있게 했다.

- 전원 켜기·끄기
- 17~30℃ 희망 온도
- 자동·냉방·제습·송풍
- 자동·약·중·강 풍량
- 풍향 이동·고정
- 경제 운전, 쾌속 냉방, 에어컨 본체 LED

온도와 모드처럼 결과 상태를 만드는 동작과 풍향·LED처럼 누를 때마다 바뀌는 순간 명령은
분리했다. 가능한 곳에서는 `POWER_TOGGLE` 대신 `POWER_OFF`, `COOL_24_HIGH`처럼 결과가
명확한 명령을 사용했다.

빠른 장면도 같은 API를 재사용한다. 장면은 기기마다 의미 기반 명령을 순서대로 실행하고,
각 결과를 성공·실패로 표시한다. 장면 편집과 기기 제어가 같은 모델 프로필을 보기 때문에
패킷이 화면 여러 곳에 중복되지 않는다.

## 6. 아이콘 문제와 로컬 아이콘 시스템

초기 시안에서 이모지와 운영체제 글꼴에 의존하자 `집에서`, `외출`, 스탠드 조명과 TV
아이콘이 환경마다 다르게 보였다. Mock 상태 글자도 초록색 배지 안에서 대비가 낮았다.

이를 해결하기 위해 Lucide 1.37.0 아이콘 자산을 프로젝트에 포함했다. CDN을 쓰지 않아
인터넷이 끊긴 집 안에서도 아이콘이 유지된다. 홈·기기·자동화·더보기 내비게이션을 포함해
25종의 아이콘을 제공하고, 사용자가 공간·기기·빠른 장면을 만들 때 직접 선택할 수 있게 했다.

Mock과 IR 연결 상태는 장식용 라운드 배지를 없애고 테마에서 읽기 쉬운 일반 텍스트로
표시했다. 빠른 장면 아이콘 위에도 여백을 늘려 카드가 답답해 보이지 않게 조정했다.

## 7. Mock 전송으로 전체 흐름 검증

송신 회로를 만들기 전에는 전송 어댑터를 `mock-ir`로 두었다. 이것은 버튼을 눌렀을 때
실제 GPIO로 출력하지 않고 다음 사항만 검증한다.

- UI가 올바른 의미 명령을 전송하는가
- 등록된 Carrier 프로필을 찾는가
- 온도·모드·풍량을 올바른 6바이트 프레임으로 변환하는가
- 명령 이력과 마지막 요청 상태가 갱신되는가
- 오류가 사용자 화면까지 전달되는가

브라우저에서 냉방 25℃ 강풍, 풍향 토글, 전원 끄기, 냉방 24℃ 강풍을 차례로 실행해 API와
화면 상태가 함께 바뀌는 것을 확인했다. 이 시점의 HTTP 200은 **명령 선택과 Mock 처리 성공**을
뜻할 뿐 에어컨이 실제로 반응했다는 뜻은 아니다.

로컬 테스트 뒤 Pi에 승인 기반으로 배포했고, 프로필을 포함한 파일 체크섬과 패키지 설치,
사용자 systemd 서비스 active 상태, Tailscale 포트 8001 응답을 확인했다.

## 8. 아직 남아 있던 것

Step 3의 끝에서 스마트홈 UI와 API 흐름은 완성됐지만 IR 상태는 다음과 같았다.

```json
{
  "transport": "mock-ir",
  "hardware_output": false
}
```

따라서 UI에서 누르면 코드와 이력은 정상적으로 움직여도 IR LED가 켜지지 않는 것이 정상이다.
다음 Step 4에서 GPIO18 송신 overlay, P2N2222A 구동 회로와 실제 `ir-ctl` 어댑터를 연결해
Mock 경계를 실하드웨어로 교체한다.

## 9. 센서 갱신 때 전체 화면을 다시 만들지 않기

라즈베리파이 키오스크에서 센서 새로고침 때 카드 전체가 다시 만들어지고 Lucide 아이콘까지
전부 변환되면서 화면이 순간적으로 무거워졌다. 센서 ID를 DOM 키로 사용해 기존 카드를
유지하고 온도·습도·문 상태·보고 시각처럼 바뀐 텍스트만 갱신하도록 변경했다. 도어 이력도
마지막 상태 변경 시각이 달라질 때만 다시 요청하고, 상세 정보와 관리 목록은 내용 서명이
달라진 경우에만 재구성한다.

![1920×1080 PC 대시보드](../assets/ui/01-desktop-dashboard-1920x1080.png)

![화면 모드와 부분 갱신 Pi 배포](../assets/terminal/50-ui-display-mode-and-render-optimization.png)

13인치 터치 키오스크에서는 마우스 포인터가 화면에 남았다. 일반 PC 웹까지 커서를 없애지
않도록 키오스크 런처만 `?kiosk=1`로 접속하고 이 경우에만 CSS 커서를 숨겼다. 두 파일의
체크섬을 확인하고 Pi를 재부팅한 뒤 웹앱, Tailscale, Cage·Chromium, Wayland와 Zigbee/MQTT
컨테이너가 모두 자동 복구되는 것까지 확인했다.

![키오스크 커서 숨김 배포와 전체 재부팅 검증](../assets/terminal/51-kiosk-cursor-hide-and-reboot.png)

## 게시 전 추가할 화면 캡처

1920×1080 데스크톱 홈 화면은 현재 버전으로 보관했다. 게시 직전에 같은 버전으로 아래 세
장을 추가하면 흐름이 더 잘 보인다.

1. 모바일 하단 내비게이션과 반응형 카드
2. Carrier CS-A061GS 제어 패널
3. 기기 추가 및 아이콘 선택 화면
