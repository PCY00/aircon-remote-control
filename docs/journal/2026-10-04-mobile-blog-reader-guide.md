# 2026-10-04 A50 스마트홈 블로그를 따라 하기 자료로 정리

## 사용자가 요청한 것

1~9편을 처음 읽는 사람도 따라 할 수 있게 쓰고, 앞 편에서 준비한 것이 다음 편으로 이어지게 정리했다. 본문에서는 ‘검증했다’, ‘점검했다’, ‘보완했다’ 대신 ‘확인했다’, ‘직접 해봤다’처럼 쉬운 표현을 사용했다. 블로그에 올릴 글과 캡처에서는 개인정보를 가렸다.

## 바꾼 글과 도구

- `docs/blog/mobile-app/00-reader-start.md`에 PC 도구 설치, 코드를 푸는 위치, 명령어를 입력할 장비와 본인 값으로 바꿀 항목을 모았다.
- 1~9편에 준비물, 실행 순서, 정상일 때 보이는 결과, 막혔을 때 볼 항목과 이전·다음 편 링크를 넣었다.
- 최신 서버와 앱 0.4.0을 설치하는 흐름으로 맞췄다. 예전 버전을 차례대로 설치하는 것으로 읽히지 않게 했다.
- 본인 장비의 연결 정보를 만드는 예시와 도구를 추가했다. 기존 설정 파일이 있으면 덮어쓰지 않는다.
- Pi 연결 도구에 있던 작성자 사용자명과 접속 대상은 공개 코드에서 뺐다. 작성자의 기존 접속 정보는 비공개 로컬 설정으로 옮겼다. Pi에 접속하거나 설정을 바꾸지는 않았다.
- 7편은 기존 Pi 센서 프로그램의 기록을 연결하는 과정임을 명시했다. 센서 프로그램을 처음부터 설치하는 설명과 혼동하지 않게 했다.

## 새 폴더에서 직접 해본 결과

코드와 글, 연결된 공개용 캡처만 골라 ZIP을 만들었다. 작성자의 실제 계정 설정, 개인 키, APK, 실행 중 생성된 기록과 로컬 도구 폴더는 넣지 않았다.

처음 실행에서 코드 형식 확인 도구가 지적한 항목을 수정했다. [처음 코드 확인 결과](../assets/terminal/366-a50-reader-initial-local-check.txt)는 그대로 남겼다.

ZIP을 새 폴더에 풀고 독립적인 Python 환경을 만든 뒤 필요한 도구를 설치했다. 설치와 도구 간 충돌 확인은 통과했지만, 첫 테스트에서는 HTTPS 통로 프로그램의 소스가 첨부 목록에 없어 멈췄다. [처음 실패 기록](../assets/terminal/367-a50-reader-fresh-folder.txt)에 실제 오류를 남겼고, 오류에 들어 있던 PC 사용자 폴더는 가렸다.

누락된 `services/central-tunnel`을 넣은 뒤 같은 독립 환경에서 다시 확인했다. **117개 테스트가 통과했고 2개는 Windows에서 실행하지 않는 Linux 파일 연결 시험이라 건너뛰었다.** 새 폴더에 작성자의 비공개 설정은 없었다. 4개 도구의 도움말도 정상적으로 열렸다. [다시 확인한 결과](../assets/terminal/368-a50-reader-fresh-folder-fixed.txt)

그다음 캡처 제목을 실제 실행 내용을 나타내는 표현으로 바꿨다. 이 제목 변경은 연결 동작에 영향을 주지 않는다. 최종 파일에서 코드 형식, 글의 명령어 연결, 이미지 정보와 공백 오류를 확인하고 ZIP을 다시 만들었다. [마지막 로컬 확인 결과](../assets/terminal/369-a50-reader-final-local-check.txt)

## 개인정보를 가린 범위

1~9편에 연결한 실제 앱 화면 10개를 직접 열어 봤다. 이메일이 보이는 가족 관리 화면은 이미 가려진 캡처를 사용한다. 알림 수신 상태 화면과 실제 알림창 사진을 혼동하지 않도록 설명도 맞췄다.

ZIP의 17개 이미지에서 위치정보 등을 담는 숨은 정보를 찾지 못했다. 본인 설정에 저장된 실제 주소, 인증 정보, 기기 식별값이 ZIP의 텍스트에 들어 있는지도 확인했다. 해당 값은 없었다. 연결된 글의 명령어 49개가 가리키는 파일과 선택 항목도 확인했다.

기존 기록 `265-a50-pi-installer-windows-symlink-failure.txt` 한 곳에서 PC 사용자 폴더를 발견해 가리고, 같은 이름의 PNG도 다시 만들었다. 오류 내용과 실패 사실은 유지했다. 저장소에 기록된 문서 텍스트에서 확인 대상인 실제 설정값과 PC 사용자 폴더가 더 남아 있지 않은 것을 확인했다. 이는 모르는 개인정보나 모든 이미지의 글자를 자동으로 읽어 찾아냈다는 뜻은 아니다.

전체 `docs/assets/`도 확인했으며 당시 453개 이미지에서 숨은 개인정보 항목은 0개였다. 마지막 로컬 확인 캡처를 추가한 뒤 454개를 다시 확인했으며 결과는 0개였다. 글에 쓰지 않은 원본 자료까지 공개 첨부에 넣지는 않는다.
