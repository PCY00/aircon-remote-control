# A50 블로그 1~9편의 문체와 흐름을 다시 썼다

사용자는 자기 티스토리 글처럼 원고를 먼저 고쳐달라고 했다. 이번 작업은 로컬 원고와 읽기용 파일을 바꾸는 범위였다. A50이나 Pi에 접속하거나 프로그램을 변경하지 않았다. 블로그 게시와 예약도 실행하지 않았다.

## 참고한 글과 적용한 말투

앞선 읽기에서 사용자의 [GPIO 버튼 글](https://kksp12y.tistory.com/230), [직접 만든 액자 글](https://kksp12y.tistory.com/100), [Pi OTG 재시도 글](https://kksp12y.tistory.com/126)을 봤다. 작업을 시작한 이유, 직접 겪은 실패, 다시 해본 과정과 사진을 이어가는 방식으로 맞췄다.

1~9편과 목차를 ‘~했다’, ‘~해보자’, ‘~임’, ‘~됨’ 중심으로 다시 썼다. 설명은 쉽게 풀고 필요한 비교는 짧은 표로 넣었다. ‘검증했다’, ‘점검했다’, ‘보완했다’ 대신 실제로 무엇을 확인했는지 적었다. 말투를 흉내 내려고 하지 않은 경험이나 결과를 만들지는 않았다.

## 실제 기록에서 가져온 장면

- 1편: SSH는 돌아왔는데 무선 디버깅은 꺼졌던 일, Wi-Fi 허용창과 드래그 잠금화면에서 멈췄던 일.
- 2편: 앱을 사용 중지해도 전체 여유 메모리는 늘지 않았던 수치. 정리 전 1,482.8 MiB, 정리 후 1,475.1 MiB였고 성능 개선이라고 쓰지 않았다.
- 3~4편: Google 로그인과 가족 권한의 차이, 자기 Firebase와 서명으로 앱을 만드는 흐름, 다른 휴대폰에서 먼저 로그인한 과정.
- 5편: 새 서비스 폴더를 알아보기 전에 시작 명령이 실행됐던 오류와 기다리도록 수정한 이유. 실행 기록 203을 연결했다.
- 6편: 전송 요청 성공과 실제 수신의 차이. 화면을 끈 A50에서 짧게 수신했던 기록 258과 화면을 다시 켠 뒤 찍은 앱 수신 상태 화면을 구분했다.
- 7편: Pi 연결 확인 알림과 온습도 기록 조회를 실제 문·온습도 알림 수신과 구분했다.
- 8편: 사용자가 이해하기 어려웠던 충돌 안내, 두 휴대폰의 서로 다른 선택 저장, 삭제 확인 화면과 실제 집 삭제의 차이.
- 9편: 저장 뒤 맨 위로 올라가던 화면, 이동 위치를 기억하도록 고친 내용, 앱이 아니라 확인 도구의 스크롤 방향 때문에 실패했던 과정.

각 편의 준비할 것, 따라 할 명령과 다음 편으로 넘어가는 기준은 유지했다. 최신 0.4.0을 한 번 설치하는 설명과 예전 작업 기록을 구분했다. 전체 과정을 새 PC와 새 폰에서 다시 실행했다고 쓰지 않았다.

## 로컬에서 확인한 것

[실행 원문](../assets/terminal/370-mobile-manuscript-style-check.txt)과 [같은 내용의 PNG](../assets/terminal/370-mobile-manuscript-style-check.png)를 남겼다.

| 항목 | 실제 결과 |
| --- | --- |
| 주요 원고 | 9편 모두 다시 썼다. |
| 명령어 묶음 | 38개 코드 블록이 수정 전과 같았다. |
| 도구 명령 참조 | 49개 참조 파일이 있었다. |
| 표 | 주요 9편에 총 20개가 있었다. |
| 앞뒤 연결 | 9편 모두 준비 항목과 이전·다음 링크가 이어졌다. |
| HTML 미리보기 | 목차 진입 페이지를 포함해 21개였다. 내부 파일 링크 86개가 있었다. |
| 공개용 그림 | 묶음에 포함한 19개 그림에서 비공개 사진 정보가 남아 있지 않았다. |
| 설정 값 | 공개 묶음의 텍스트에 실제 비공개 설정 값, 이메일과 임시 서버 주소가 남아 있지 않았다. |

로컬 HTML에서는 230번 글의 청록색 표 머리행을 적용했다. Chrome에서 실제 색이 `rgb(110, 211, 216)`, 본문 안의 표 폭이 760px인 것을 봤다. 2편의 표·본문 간격과 8편의 실제 폰 화면을 눈으로 확인했다. 8편의 그림 3개가 모두 열렸고, 폰 그림은 420px로 표시해 긴 화면이 과하게 커지지 않게 했다.

미리보기의 상대 링크도 압축을 풀어 볼 수 있도록 연결했다. 실제 티스토리 편집기에 넣어본 것은 아니다. 나중에 게시할 때는 그림을 함께 올리고 편집기에서 배치를 다시 확인해야 한다.

코드나 명령어는 바꾸지 않아서 앱·서버 시험을 다시 실행하지 않았다. 이번 확인은 원고 흐름, 명령어 유지, 파일 링크와 공개 자료에 대한 확인이었다.

## 저장 위치

기준 원고는 `docs/blog/mobile-app/`에 있다. 바탕화면의 `smart-home-reader-v0.4.0.zip`을 새 원고로 다시 묶었다. 183개 파일이며 기준 소스 181개의 내용이 실제 ZIP과 같았다. 기존 ZIP은 수정 전 해시를 확인한 뒤 로컬 임시 폴더에 보관했다.

글을 보기 위한 `A50-블로그-원고.zip`도 같은 공개 자료를 사용해 만들었다. 미리보기와 안내·파일 목록을 포함해 204개 파일이다. 실제 비공개 설정 값이 포함되지 않았고 그림 19개에서 비공개 사진 정보가 남아 있지 않은 것을 ZIP 안에서도 확인했다. 바탕화면으로 복사한 두 ZIP의 내용도 원본과 같았다. 이 파일들의 게시와 자동 예약은 별도 작업이다.
