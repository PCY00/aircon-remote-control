# 2026-10-02 — Pi의 기존 기록과 가족 중앙 서버 연결 준비

현재 상태: 아래 승인 전 준비 이후 사용자 승인으로 실제 집 연결·Pi발 화면 꺼짐 FCM 수신·자동 전송 서비스 시작·새 서비스 재시작 후 보존까지 확인했다. 물리 문 변화·다른 가족 단말·장시간 검증은 남아 있다.

사용자 요청에 따라 기존 Pi의 문·자동화 기록을 A50에 연결하는 작업을 시작했다.
확인된 기존 SSH 대상·키·프로젝트 경로만 사용했다. Pi 제어 서비스 active, Python 3.13.5.
문 552건·자동화 150건, 원본 DB 두 개 무결성 ok. 원격 앱 여섯 파일의 차이는 9월 12일
미배포 로컬 개선과 일치했다. 원격 앱을 덮어쓰지 않고 독립 연결 서비스를 구현했다.

구현: 읽기 전용 원본 DB 조회, 첫 시작 이전 기록 건너뛰기, 별도 SQLite 대기열·안정적인 이벤트 ID,
최대 8회 재시도·발생 후 240초 만료·로그/서비스 시작 제한. 문 변화·경고 발생/해제만 전송하며
MAC·방 이름·원시 MQTT·snapshot은 제외한다. 중앙 0.3.1은 원래 만료시간을 유지한다.

오류: Windows 임시 설치 검사에서 WinError 1314. Linux 링크 권한의 환경 차이여서 해당 2개
검사를 Pi `/tmp/aircon-agent-install-test-*`에서 실행했다. systemctl은 대체 함수라 운영 서비스
명령을 실행하지 않았다. 실제 링크·체크섬·원격 편집 보존 모두 통과했다. 최초 래퍼는 cp949
출력으로 UnicodeEncodeError도 났다. 실제 실패 TXT는 저장된 상태였고 이후 stdout을 UTF-8로 설정했다.
import 정렬 후 경로 준비보다 먼저 `a50_record`를 가져와 ModuleNotFoundError가 났다.
`pi_session`의 명시적 export로 수정한 뒤 연결 미리보기가 통과했다.
JUnit 첫 상태 메시지에 클래스명이 붙음을 실제 소유자 출력에서 확인해 준비 신호 검사를 수정했다.

최종 로컬 88개 통과, Windows의 Linux 전용 2개 제외. 제외한 2개는 실제 Pi 임시 검사에서 통과.
응답 유실 재시도에서도 중앙 기록 1건·원래 만료·해당 가족만 대상으로 유지함을 검사했다.
시험 APK 빌드 성공(591,129바이트), 배포 APK 0.2.0·기존 실제 Google 계정은 보존했다.

Pi 실제 배포 미리보기: 관리 파일 2개, release a708bac1e869c120, 기존 앱·DB 갱신 없음.

준비 상태 200·동시 조회 8회·루프백 바인딩·외부 TLS·인증 없음/위조 401을 확인했다.
터널 PID 유지. 실제 Google 소유자 검사 통과(2.841초), ‘A50 테스트 집’의 등록 허브 0개.

## 사용자 승인 후 실제 연결과 운영 확인

사용자가 전용 허브 키·‘A50 테스트 집’ 연결·자동 전송을 승인했다. 기존 앱과 원본 DB를 바꾸지 않는 독립 Pi 경로와 서비스 영향을 먼저 안내한 뒤, 준비된 연결 도구를 적용했다.

- 실제 Google 소유자 사전 확인 통과: 1.957초. 배포 APK·기존 계정 유지.
- Pi 독립 릴리스 a708bac1e869c120의 관리 소스·서비스 파일 체크섬 일치. 기존 문 552건·자동화 150건의 DB는 읽기 전용으로 확인했다.
- 전용 허브 키를 A50 비공개 운영 파일과 Pi 비공개 설정에 연결했다. 두 설정 권한 0600. 서비스 계정 키는 Pi에 보내지 않았다.
- 실제 앱의 Firebase SDK와 소유자 API로 일회용 연결 코드를 소비해 승인된 집에 묶었다. 소유자 연결 검사 0.959초 통과. 짧은 수명의 전달 파일은 노트북과 앱에서 제거했다. 긴 허브 키·Google ID 토큰을 로그·저장소에 기록하지 않았다.
- 첫 시작은 이전 기록 702건을 건너뛰고 문 552·자동화 150 위치를 저장했다. 과거 알림 재발송 없음.
- 실제 Pi에서 연결 시험 이벤트 1건을 발송했다. 화면이 꺼진 A50 앱에서 실제 FCM 콜백과 알림 게시, 해당 집 이벤트 기록을 확인했다. 검사 8.137초 통과. 이는 물리 센서를 움직인 시험이 아니다.
- 중앙 현재 집 2·허브 1·이벤트 1·설치 1. 다른 집 이벤트 0. FCM accepted 4건은 이전 직접 시험 3건과 이번 Pi 연결 시험 1건이다.
- 자동 전송 서비스를 active/enabled로 시작했다. user linger는 기존 yes였다. 초기 RSS 26,368kB, 운영 대기 0·연결 시험 accepted 1. 기존 에어컨 서비스 active와 원격 앱 여섯 파일의 기존 체크섬을 유지했다.
- 새 연결 서비스만 한 번 재시작했다. 개인 설정·키 식별·진행 위치·대기열·이벤트 ID가 전후 일치했다. 원본 DB 무결성 ok, 재전송·과거 기록 발송·자동 재시작 반복 없음. Pi 전체 재부팅은 하지 않았다.
- 읽기 전용 점검 도구 scripts/pi/verify_central_agent.py를 추가하고 실제 Pi·A50에서 통과했다. 재시작 후 RSS 26,364kB, 중앙 집 연결과 기존 결과 유지.

마지막에는 A50을 홈 화면으로 돌리고 화면을 껐다. 자체 관리 상태 interactive=false·무선 ADB 유지·SSH 준비 상태 통과를 확인했다. 일회용 전달 파일이 앱과 노트북 양쪽에 없는 것도 재확인했다.

실행 자료: 터미널 284~297 TXT/PNG, 실제 수신 후 앱 화면 [13번 캡처](../assets/hardware/family-app/13-a50-pi-connection-fcm-receipt.png). 화면 캡처는 수신 검증 뒤 화면을 켜서 촬영했으며, 화면 꺼짐 수신 증거는 290번 실제 검사 출력이다.

비용 질문에는 FCM과 현재 Google 로그인 사용량이 무료 범위이고, 결제 계정·유료 서버·도메인을 신청하지 않았다고 답했다. 기존 기기의 전기·통신비는 별도이며 측정하지 않았다. 사용자의 Google 계정 전체 청구 내역을 조사한 것은 아니다. 공식 요금 근거는 블로그 7편에 링크했다.


## 새 휴대폰에서 시험 알림 등록 안내

사용자가 같은 Google 계정으로 다른 휴대폰에 APK를 설치한 뒤 시험 알림의 충돌 문구를 보고했다.
서버 읽기 전용 점검에서 활성 설치 1개·accepted 4개·전송 오류 없음이었다.
0.2.0은 설치 미등록 HTTP 409도 일반 충돌 문구로 표시함을 소스로 확인했다.
각 휴대폰에서 별도 알림 켜기·등록 완료 확인 후 시험하도록 안내했다. 사용자 휴대폰의
알림 설정 상태와 최종 수신은 확인 대기이며, 실제 등록 충돌이라고 단정하지 않았다.
동일 계정 두 설치의 집 이벤트 동시 수신 대상 선정과 지정 설치만 시험 전송하는 회귀 검사를
추가했다. 관련 Python 검사 15개 통과. 운영 코드·APK·서버 등록은 변경하지 않았다.
원문·PNG는 298~299, 재현 순서는 troubleshooting.md에 보존했다.
