# 2026-10-02 — Pi의 기존 기록과 가족 중앙 서버 연결 준비

사용자 요청에 따라 기존 Pi의 문·자동화 기록을 A50에 연결하는 작업을 시작했다.
확인된 기존 SSH 대상·키·프로젝트 경로만 사용했다. Pi 제어 서비스 active, Python 3.13.5.
문 552건·자동화 150건, 원본 DB 두 개 무결성 ok. 원격 앱 여섯 파일의 차이는 9월 12일
미배포 로컬 개선과 일치했다. 원격 앱을 덮어쓰지 않고 독립 연결 서비스를 구현했다.

구현: 읽기 전용 원본 DB 조회, 첫 시작 이전 기록 건너뛰기, 별도 SQLite 대기열·안정적인 이벤트 ID,
최대 8회 재시도·발생 후 240초 만료·로그/서비스 시작 제한. 문 변화·경고 발생/해제만 전송하며
MAC·방 이름·원시 MQTT·snapshot은 제외한다. 중앙 0.3.1은 원래 만료시간을 유지한다.

오류: Windows 임시 설치 검사에서 WinError 1314. Linux 링크 권한의 환경 차이여서 해당 2개
검사를 Pi `/tmp/aircon-agent-install-test-*`에서 실행했다. systemctl은 대체 함수라 운영 서비스
명령을 실행하지 않았다. 실제 링크·체크섬·원격 편집 보존 모두 통과했다. 최초 래퍼는 cp949
출력으로 UnicodeEncodeError도 났다. 실제 실패 TXT는 저장된 상태였고 이후 stdout을 UTF-8로 설정했다.
import 정렬 후 경로 준비보다 먼저 `a50_record`를 가져와 ModuleNotFoundError가 났다.
`pi_session`의 명시적 export로 수정한 뒤 연결 미리보기가 통과했다.
JUnit 첫 상태 메시지에 클래스명이 붙음을 실제 소유자 출력에서 확인해 준비 신호 검사를 수정했다.

최종 로컬 88개 통과, Windows의 Linux 전용 2개 제외. 제외한 2개는 실제 Pi 임시 검사에서 통과.
응답 유실 재시도에서도 중앙 기록 1건·원래 만료·해당 가족만 대상으로 유지함을 검사했다.
시험 APK 빌드 성공(591,129바이트), 배포 APK 0.2.0·기존 실제 Google 계정은 보존했다.

Pi 실제 배포 미리보기: 관리 파일 2개, release a708bac1e869c120, 기존 앱·DB 갱신 없음.
A50 중앙 0.3.1-fc03a7555b62d530을 미리보기 뒤 반영했다. 일관 SQLite 백업·소스/후크 체크섬 일치,
준비 상태 200·동시 조회 8회·루프백 바인딩·외부 TLS·인증 없음/위조 401을 확인했다.
터널 PID 유지. 실제 Google 소유자 검사 통과(2.841초), ‘A50 테스트 집’의 등록 허브 0개.
현재 사용자 1·집 2·허브 0. 실제 Pi 키 발급·집 연결·새 서비스 자동 시작은 승인 전이다.

다음: 전용 허브 키·소유자 집 연결·자동 전송 확인 후 일회용 코드 소비 → 과거 기록 건너뛰기 →
실제 연결 이벤트·화면 꺼짐 FCM 수신 → 서비스 자동 시작. 새 물리 문 변화·다른 가족 단말·장시간
시험은 별도다. 현재 준비를 운영 연결 완료로 기록하지 않는다.
