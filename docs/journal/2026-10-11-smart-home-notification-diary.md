# 스마트홈 알림 일기 — 2026-10-11

## 사진에 나온 GitHub 도구 여섯 개를 찾아봤다

　사진에 적힌 프로젝트가 무엇이며 지금 작업에 도움이 되는지 궁금하다는 이야기가 나왔다. 각 프로젝트의 공식 GitHub 소개와 사용 조건을 읽었다. 처음 두 주소를 잘못 읽어 페이지를 열지 못했고, 프로젝트 이름으로 다시 찾아 OpenRig와 AnyPS5의 실제 저장소를 확인했다.

　OpenRig는 여러 AI 개발 도구를 팀처럼 묶고 역할과 작업을 나누는 도구였다. 앱·서버·문서를 나누어 만드는 데 쓸 수 있지만 설치와 관리가 추가된다. Windows에서는 WSL2가 필요하다고 안내하고 있었다.

　AnyPS5는 PS5 실행 파일을 Linux와 Windows에서 실행할 수 있게 옮기는 도구였다. 현재 스마트홈과 블로그 작업에는 직접 연결되는 용도가 없다고 판단했다.

　HyperFrames는 HTML과 CSS로 만든 화면과 움직임을 MP4 영상으로 만드는 도구였다. 기존 글의 자료를 바탕으로 스마트홈 구조 설명이나 짧은 시연 소개 영상을 만들 때 도움이 될 것으로 봤다. 실제 작동 장면은 직접 찍은 영상을 넣어야 하며, 이번에는 영상을 만들거나 도구를 설치하지 않았다.

　Cursor plugins는 Cursor용 기능과 작업 방법을 모아둔 저장소였다. 코드 확인과 문서 작업 방식을 참고할 수 있지만 현재 도구에 그대로 설치된다고 확인한 것은 아니다.

　NVIDIA OpenShell은 AI가 접근할 파일과 네트워크 범위를 제한하는 실행 환경이었다. 나중에 AI에게 서버 관리 작업을 맡길 때 참고할 만했다. 가족별 집 권한이나 FCM 알림 분리 기능을 대신하는 것은 아니라고 구분했다.

　Agent-Reach는 웹페이지·GitHub·유튜브 자막과 여러 사이트의 자료를 읽는 데 필요한 도구들을 연결하는 구성이었다. 블로그 참고 자료와 개발 문제 해결 사례를 모을 때 도움이 될 수 있다. 일부 사이트는 로그인이나 별도 설정이 필요하고 티스토리 자동 게시 도구는 아니었다. 현재 가능한 웹 검색과 겹치는 부분도 있어 꼭 설치할 필요는 없다고 봤다.

　이번에는 문서를 읽고 사용 가능성을 비교한 단계다. A50과 Pi의 설정·코드는 바꾸지 않았다. 추천은 현재 작업에 맞춘 판단이며 실제 설치와 작동 확인 결과는 아니다.

　노션의 오늘 일기 경로와 저장한 내용을 다시 읽어 확인했다.

## 서버가 다시 켜진 뒤 앱에서 집이 사라졌다는 문제를 확인했다

　서버가 꺼졌다 켜진 뒤 가족 앱에서 내 집이 보이지 않는다는 이야기가 나왔다. 새 집을 만들기 전에 기존 등록 데이터가 남아 있는지, 앱이 같은 서버와 계정에 연결되는지 차례로 확인했다.

　A50에 원격으로 연결해 저장 파일을 읽었다. 현재 사용 중인 집 1개와 그 집의 가족 등록 1개가 남아 있었고 저장 파일 상태도 정상이었다. 과거 비활성 집 1개도 따로 남아 있어 전체 개수와 현재 사용하는 개수를 구분했다. 새 집을 만들거나 데이터를 지우지는 않았다.

　현재 외부 HTTPS 주소로 서버가 응답하는 것을 확인했다. 로그인 정보가 없거나 가짜인 요청은 계속 거절했다. 지금 연결 방식은 임시 주소를 쓰기 때문에 연결 프로그램이 다시 시작되면 주소가 바뀔 수 있었다. 사용자도 앱에 ‘서버 연결·주소 오류’가 뜬다고 알려줬다. 이전 주소로 연결하는 상황이 유력하지만 사용자 휴대폰에 저장된 주소를 직접 읽어 비교한 것은 아니다.

　현재 주소를 사용자에게 따로 안내하고 앱의 연결 설정에 저장한 뒤 같은 Google 계정으로 로그인하도록 했다. 실제 주소는 공개 기록에 남기지 않았다. 이후 사용자가 ‘기존 집이 보여’라고 알려줘 현재 주소를 통한 기존 집 복구를 확인했다.

　앱 코드를 읽어보니 서버의 답을 받기 전부터 ‘아직 연결된 집이 없어요’를 보여주고 있었다. 처음 연결 중인 상태, 연결 실패, 서버가 실제로 빈 목록을 준 상태를 나눴다. 연결 실패 때에는 오류와 다시 연결·연결 설정 버튼을 보여주고 같은 로그인 상태에서 이미 읽은 집은 마지막으로 확인한 목록이라고 표시하게 했다. 계정이나 서버를 바꿀 때에는 이전 집 목록을 지우게 했다.

　수정 APK 0.4.1의 개발용·배포용 파일을 만들었다. 집 목록 관련 4개를 포함한 단위 확인 8개를 통과했다. 기존 서명과 같은지, 배포용이 HTTPS를 사용하는지, 시험용 계정 자료가 섞이지 않았는지 확인했다. 배포용 APK를 바탕화면에 복사하고 원본과 같은 파일인지도 확인했다. A50의 화면 연결은 실패해 새 화면의 실기기 확인은 아직 하지 못했다. SSH와 서버 연결은 계속 가능했다.

　임시 주소 자체가 고정된 것은 아니어서 고정 주소 준비는 남아 있다. 현재 주소 안내와 집 목록 오류 표시를 바꾼 범위를 구분했다. `server/docs/troubleshooting.md`에 같은 문제가 생겼을 때 따라 할 순서를 남겼다.

## 가족 앱에서 에어컨을 켤 수 있는지 물어봤다

　현재 가족 앱에는 문 열림·온습도 알림과 기록 조회, 가족 관리가 있고 에어컨 조작은 Pi의 웹 화면에서 사용한다고 설명했다. 가족 앱에서 에어컨을 켜려면 앱에서 A50을 거쳐 해당 집의 Pi로 명령을 보내는 연결이 필요하다. 집별 조작 권한과 실제 실행 결과를 함께 확인해야 한다고 설명했고 이번에는 에어컨 제어 기능을 새로 구현하지 않았다.

## 가족 앱에서도 에어컨을 켜고 끌 수 있게 만들었다

　가족 앱에서도 에어컨을 켜고 끌 수 있게 만들어 달라는 요청을 받았다. 앱에 냉방 24°C·바람 자동으로 켜기와 전원 끄기를 추가했다. 집 소유자와 가족은 조작할 수 있고 조회 전용 계정과 다른 집 사람의 요청은 서버가 거절하도록 했다. 보내기 직전에도 가족 권한과 기기 연결을 다시 확인하게 했다.

　앱이 A50에 명령을 맡기면 해당 집의 Pi가 기존 HTTPS 통로에서 받아가는 방법으로 연결했다. 공유기 포트를 새로 열거나 유료 서비스를 연결하지 않았다. 기존 A50과 Pi의 전기·인터넷 비용은 그대로이며 도메인을 구매하지 않았다.

　명령은 30초가 지나면 실행하지 않게 했다. Pi는 실행 전에 기록을 남기고 결과를 잃거나 다시 켜져도 같은 명령을 자동으로 다시 보내지 않게 했다. 결과 보고만 다시 보낼 수 있게 나눴다. IR 송신 완료는 실제 에어컨 전원 상태를 읽은 값이 아니라고 앱에 안내했다.

　처음 Pi의 로컬 주소로 에어컨 목록을 읽으려 했을 때 연결되지 않았다. 기존 웹 서비스가 Tailscale 주소에만 연결돼 있었기 때문이었다. 실행 중인 서비스의 실제 주소와 포트를 읽고 기존 사설 연결을 그대로 이용하게 했다. 웹 서비스의 공개 범위는 바꾸지 않았다.

　A50의 저장 파일을 백업한 뒤 중앙 서버를 0.5.0으로 올렸다. 현재 사용하는 집 1개와 가족 등록 1개가 남아 있고 저장 파일이 정상임을 확인했다. Pi의 알림 연결 서비스만 업데이트했고 기존 에어컨 웹 서비스는 다시 시작하지 않았다. A50에서 Pi와 에어컨 1대의 연결 상태를 읽었고 로그인 정보가 없는 조작 요청은 거절했다. 실제 IR 명령은 보내지 않았다.

　서버·Pi 자동 확인은 최종 138개가 통과했고 Windows에서 실행하지 않는 2개는 건너뛰었다. 앱 단위 확인 10개와 개발용·배포용 APK 만들기도 끝났다. 기존 앱과 같은 서명인지, 배포용이 HTTPS를 사용하는지, 시험 자료가 섞이지 않았는지 확인했다. 배포용 0.5.0 APK를 바탕화면에 복사하고 원본과 같은 파일임을 확인했다. A50의 화면 연결은 되지 않아 새 화면과 실제 에어컨 반응은 아직 확인하지 못했다. 따라 할 순서는 `server/docs/aircon-app-control.md`에 남겼다.

## 연결된 H2의 기존 프로그램을 확인하고 재기록을 준비했다

　사용자가 새 APK는 아직 설치하지 않았고 H2 펌웨어부터 다시 올려 달라고 했다. 앱 설치와 실제 끄기 시험은 뒤로 미뤘다. USB로 연결된 ESP32-H2와 4 MB 플래시를 확인하고 현재 Zigbee IR 코드로 빌드를 끝냈다. 파일 크기는 511,168바이트였다.

　플래시 전체를 저장소 밖에 비공개로 백업한 뒤 저장 공간 배치를 비교했다. 현재 보드의 프로그램 시작 위치는 `0x10000`으로 기본 빌드의 `0x20000`과 달랐다. 첫 시도는 비교 단계에서 멈췄고 펌웨어를 쓰지 않은 채 기존 프로그램을 다시 실행했다. USB 출력에서 `G V2 수동 시험` 프로그램이 들어 있는 것을 확인했다.

　다른 프로그램을 임의로 덮어쓰지 않으려고 어느 펌웨어인지 물었다. 사용자는 스마트홈 에어컨용 Zigbee IR이라고 답했다. 기존 저장 공간 배치와 설정 영역은 그대로 두고, 실제 프로그램 시작 위치를 읽어 그 영역만 교체하는 방법으로 진행했다. 전체 초기화나 Zigbee 등록 정보 삭제 명령은 사용하지 않았다. 이 시점에는 재기록과 연결 복구 결과를 아직 기다리고 있었다.

## H2 프로그램을 다시 올렸고 Pi에서 다시 나타난 기록을 확인했다

　실제 프로그램 위치인 `0x10000`에만 다시 썼다. 다시 읽은 511,168바이트가 빌드 파일과 정확히 같았고 프로그램 영역 밖의 플래시는 그대로였다. 새 프로그램이 정상 실행됐지만 첫 Zigbee 연결에는 `0x03` 오류가 있었다. USB 보드와 Pi에 등록된 H2의 식별값을 비공개로 비교했고 같았다.

　사용자가 최대 120초의 가입 허용을 승인했다. 가입을 여는 사이 USB가 사라져 PC에서 다시 켜지 못했다. 첫 닫기 시도는 이미 가입이 열려 있으면 멈추는 사전 조건 때문에 실패했다. 닫기만 수행하도록 바꾼 뒤 가입 허용이 꺼진 상태를 실제로 읽었다. 사용자는 H2를 다른 전원과 위치로 옮겼다고 했고 이어 연결됐다고 알려줬다. Pi의 최근 기록에서도 같은 H2의 재등장 1건과 지원 상태를 확인했다. 실제 에어컨 명령은 보내지 않았다.

　PC용 C 시험에서는 실제 코드가 쓰는 GPIO5가 시험용 이름 목록에 없어 7개가 컴파일되지 않았다. 시험용 이름을 추가하고 다시 실행해 Zigbee와 USB IR 코드의 확인 9개를 통과했다. 실제 펌웨어의 핀과 배선은 바꾸지 않았다. 과정과 실패·해결은 `docs/journal/2026-10-11-h2-firmware-restore.md`와 실제 터미널 기록에 남겼다.

## 앱에서 빠진 온도·모드·풍향 조작도 이어서 넣기로 했다

　사용자가 기존 온도·풍향·냉방 명령이 앱에는 왜 없는지 물었다. 처음 앱 연결을 냉방 24°C 켜기와 끄기로 제한해서 나머지 조작이 빠졌다고 설명했다. H2에는 기존 명령이 이미 들어 있어 이번 기능 추가를 위해 다시 올릴 필요는 없다고 구분했다. A50·Pi의 전달 코드와 APK를 함께 바꾸고 사용자는 새 APK를 설치하는 순서로 진행했다.

## 기존 H2 펌웨어를 유지하고 앱의 나머지 조작을 완성했다

　사용자가 H2 펌웨어는 괜찮고 앱만 업데이트하면 되는지 물었다. H2에는 온도·바람·모드·풍향 명령이 이미 들어 있으며 재기록과 정상 실행을 확인했으므로 이번 기능 때문에 다시 올릴 필요는 없다고 설명했다. A50·Pi의 전달 코드도 같이 바꿔야 하지만 그 부분은 원격으로 반영했다. 사용자가 해야 할 일은 새 APK를 기존 앱 위에 설치하는 것이다. 모든 명령의 실물 반응을 확인했다는 뜻은 아니라고 구분했다.

　앱 0.5.1에 별도 에어컨 조작 화면을 만들었다. 냉방 17–30°C와 바람 자동·약·중·강, 자동·제습·송풍, 풍향 고정·스윙·절전·터보·표시등·끄기를 연결했다. 값을 고르는 것만으로는 보내지 않고 설정 보내기와 확인을 거치게 했다. 화면이 새로 읽힐 때 선택한 값과 스크롤 위치를 유지하며 스윙과 표시등은 누를 때 현재 상태를 바꾸는 기능이라고 안내했다.

　서버·Pi 자동 확인 216개가 통과했고 Windows에서 실행하지 않는 2개는 건너뛰었다. 허용된 66개 요청이 기존 Pi 명령까지 이어지는 것은 가짜 송신 장치로 확인했다. 앱 단위 확인은 13개가 통과했다. 첫 APK 만들기에서는 새 시험 코드의 함수 이름을 잘못 써서 멈췄다. 이름을 고친 뒤 개발용·배포용 APK를 모두 만들었고 기존 서명·HTTPS 사용·시험 자료 제외도 확인했다.

　A50의 저장 파일을 백업하고 중앙 서버를 0.5.1로 바꿨다. Pi의 독립 연결 서비스도 바꿨으며 배포한 코드가 로컬과 같은지 확인했다. 원래 Pi 웹 서비스는 다시 시작하지 않았다. 기존 집·가족·허브 등록과 알림 선택은 남아 있었고 저장 파일 상태는 정상이었다. 중앙 서버가 Pi와 에어컨 1대를 읽었고 외부 HTTPS 상태 확인은 200이었다. 로그인 정보가 없는 제어 요청은 401로 거절했다.

　A50의 화면 연결은 되지 않아 새 앱 설치와 실기기 화면 캡처는 하지 못했다. 이번 확인에서 실제 에어컨 명령은 보내지 않았다. 새 APK 설치 후 앱의 결과와 실물 반응을 확인하는 일이 남았다. 연결 주소는 여전히 시험용 임시 주소이므로 나중에 주소가 바뀌면 연결 설정도 맞춰야 한다.

## 업데이트 설치 파일과 따라 할 기록을 정리했다

　배포용 `가족-스마트홈-v0.5.1.apk`를 바탕화면에 저장하고 원본과 같은 파일인지 다시 읽어 확인했다. 기존 앱과 같은 서명이므로 앱을 삭제하지 않고 그 위에 설치하면 된다. 집 화면에서 에어컨 조작을 열고 값을 고른 뒤 설정 보내기를 누르는 순서다.

　H2 재기록·연결 실패와 복구, APK 만들기 실패와 수정, 서버·Pi 반영과 확인 결과를 실제 출력의 TXT·PNG로 남겼다. 공개 기록에서 사용자 경로와 접속 정보를 가렸고 이미지 437개의 비공개 메타데이터가 0개인 것을 확인했다. `server/MANIFEST.json`의 공개 파일 277개도 실제 파일과 같은지 확인했다. 노션의 오늘 스마트홈 알림 페이지를 다시 읽어 저장된 내용을 확인했고 같은 내용을 로컬 일기에도 남겼다. 새 APK의 실기기 화면과 실제 에어컨 반응 확인은 계속 남아 있다.
