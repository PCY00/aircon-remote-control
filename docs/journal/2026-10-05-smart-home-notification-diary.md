# 2026-10-05 스마트홈 알림 일기

## 10:28 · 코드 첨부 대신 GitHub 링크로 안내하기

　블로그에 코드 ZIP을 첨부하는 대신, 코드를 GitHub에 올리고 공개 링크를 넣으면 되는지 이야기했다. 이미 공개 저장소가 있으므로 압축을 푼 파일을 중복 폴더에 넣기보다 기존 코드 위치에 필요한 파일을 올리기로 했다.

　게시용 자료 안의 코드 175개를 공개 저장소와 비교했다. 준비 도구와 설정 예시, 시작 안내 등 13개가 아직 공개 저장소에 없었다. 최근 글 수정도 로컬에만 남아 있었다. 첫 글과 시작 안내를 GitHub에서 내려받는 방식으로 바꾸고 있다. 이후 코드가 바뀌어도 같은 자료를 받을 수 있도록 `smart-home-reader-v0.4.0`이라는 이름으로 이번 코드를 고정할 예정이다.

　10월 5일의 일기 경로를 읽고, 기존 다른 주제의 기록을 유지하면서 스마트홈 알림 페이지를 만들었다. 실제 저장한 내용을 다시 읽었다. 공개 저장소 반영과 새 게시용 HTML 확인은 진행 중이다.

## 10:38 · 요청한 server 폴더에 올렸다

　추가 답변으로 업로드 위치가 GitHub 저장소의 `server` 폴더임을 확인했다. 공개할 코드·글·사진 175개를 이 폴더에 넣었다. 기존 설치 안내는 유지하면서 안쪽 폴더에서 실행하는 방법과 본인 Pi 접속 설정을 준비하는 경로를 고쳤다. 개인정보와 실제 설정값, 인증키는 넣지 않았다.

　옮긴 폴더에서 자동 확인을 실행했다. 117개가 통과했고 2개는 건너뛰었다. GitHub의 기본 브랜치에는 이번 `server` 자료와 메인 안내만 올렸다. 현재 로컬 작업 브랜치와 다른 원고 수정은 유지했다. 서버·가족 앱 0.4.0의 코드가 바뀌지 않도록 `smart-home-reader-v0.4.0` 이름도 함께 만들었다.

　실제로 GitHub에서 압축 파일을 내려받아 확인했다. 첫 확인에서는 `scripts/reader/render_tistory_markdown.ps1`의 파일 비교가 멈췄다. 공개 파일의 Windows 줄바꿈과 Git 원문의 줄바꿈이 다르기 때문이었다. 줄바꿈을 같은 방식으로 맞춰 다시 비교하니 코드 175개가 전부 같았다. `server`에는 안내와 파일 목록을 포함해 177개가 들어 있었다. 설치 안내의 링크, 글 9개의 흐름과 명령어가 가리키는 파일 49곳도 확인했다.

　첫 글과 게시 안내에서 코드 ZIP을 직접 첨부하라는 문구를 바꿨다. 이제 공개 GitHub 링크를 열고 Code → Download ZIP을 누르면 된다. 내려받는 ZIP에는 저장소 전체가 들어 있으므로 안쪽 `server` 폴더를 사용하도록 적었다. 티스토리 본문 HTML에는 공개 코드 링크 하나가 들어갔으며, 로컬 문서나 사진 주소는 없었다. 바탕화면의 게시용 ZIP도 새 원고로 갱신했다. 실제 실행 출력은 터미널 기록 373의 TXT와 PNG로 남겼다.

　오늘은 GitHub 코드 공개와 원고 안내를 바꿨다. A50나 Pi에 새로 배포하거나 기기를 재시작하지 않았고, 실제 센서 알림이나 티스토리 게시 완료를 새로 확인한 것은 아니다.

　터미널 기록 이미지를 처음 만들 때 출력 파일 인수를 빠뜨려 저장이 멈췄다. PNG 경로를 함께 지정해 다시 실행했고 이미지가 저장됐다. 새 이미지에 위치정보 같은 숨은 개인정보가 없는지도 확인했다. 마지막으로 GitHub 기본 브랜치와 고정 버전이 같은 업로드 내용을 가리키는지, 오늘 노션 일기가 5일의 올바른 위치에 저장됐는지 다시 읽었다.

## 루트의 A50 중복을 정리했다

　루트와 `server`가 겹치는지 확인해 달라는 요청을 받았다. 공개 파일 177개를 비교하니 145개는 루트의 같은 경로와 내용까지 같았고, 18개는 내용이 달랐다. 14개는 `server`에만 있었다. 이후 루트에는 A50 서버 관련 코드가 없어야 하고 README에서 소개하는 것은 괜찮다는 방향을 확인했다.

　공개 루트의 세 설치 도구는 예전 방식이었다. `server`의 도구는 본인 Pi 접속 설정을 읽고, 현재 서버 0.4.0의 첫 연결을 허용하며, 기록 파일이 없는 새 폴더에서도 시작할 수 있었다. 로컬 수정본은 `server`의 내용과 같았다. 삭제 전에 각 파일을 비교하고 원본을 비공개 백업으로 남겼다. 빠져 있던 A50 확인용 Java 파일과 Pi 연결 시험 파일도 `server`로 옮겼다.

　정리 도구는 내가 먼저 바꾼 자료 생성 도구의 차이에서 멈췄다. 새 테스트 파일을 묶음에 넣는 세 줄의 변경임을 확인했고 그 차이만 허용해 계속했다. 코드 백업을 접속 설정 폴더에 두자 개인정보 확인 도구가 예시의 가짜 값을 실제 설정값으로 오인했다. 백업은 Git에서 제외되는 임시 폴더로 옮겨 보존했고 개인정보 확인은 그대로 실행했다. 다시 확인한 결과 실제 비공개 값과 사진의 숨은 개인정보는 없었다.

　A50 전용 앱·서비스·설치 도구·테스트와 글은 `server` 한 곳에 모았다. 루트에서 정리한 로컬 파일은 153개였고, 공개 GitHub에 기존에 있던 파일은 140개였다. 기존 PC의 접속 설정은 그대로 유지한 채 옮긴 도구도 같은 설정을 읽도록 로컬 경로를 연결했다. 이 연결과 비공개 설정은 Git에서 제외됐다.

　Pi 쪽 자동 확인은 97개가 통과했다. 기존 Windows 경로에서 빌드가 막히는 H2 IR 파일은 이번에도 제외했다. A50 쪽은 119개가 통과했고 2개는 건너뛰었다. 별도 `pytest.ini`를 넣어 `server`에서 A50 테스트를 따로 찾도록 했다. 전체 구조도의 코드 위치 50곳과 문서 링크도 새 경로로 바꿨다. A0 PDF는 한 페이지였고 한글을 읽을 수 있었으며 래스터 이미지는 없었다.

　GitHub 기본 브랜치에 폴더 정리와 관련 경로 변경을 올렸다. Pi의 `app`, `firmware`, `deploy`, 장치 프로필과 기본 설치 설정은 바뀌지 않았다. 이전 고정 버전은 유지하고, 정리한 자료를 받을 `smart-home-reader-v0.4.0-r1`을 새로 만들었다. 실제 공개 ZIP을 내려받아 루트의 A50 전용 코드가 0개인지와 `server` 코드 178개가 올린 내용과 같은지 확인했다. `server`에는 안내와 목록을 포함해 180개 파일이 있었다.

　블로그 첫 글의 링크와 게시용 ZIP도 새 버전으로 바꿨다. 실행 출력과 오류·해결 과정은 터미널 기록 374의 TXT와 PNG로 남겼다. 이번 일은 저장소 정리였으며 실제 A50·Pi에 코드를 새로 배포하거나 센서를 새로 시험한 것은 아니다.

## 10:56 · 고정 버전 내려받기 안내를 없앴다

　`server/README.md`의 ‘글에서 사용한 코드 0.4.0’ 링크가 이제 필요 없다는 요청을 받았다. 해당 링크와 버전 이름을 지정하는 Git 내려받기 명령을 없앴다. 이제 `main`의 현재 코드를 받고, 압축을 푼 뒤 안쪽 `server` 폴더를 사용한다.

　루트 README와 시작 안내, 첫 글과 목차, 게시용 HTML 생성 도구도 같은 방향으로 바꿨다. 첫 글의 공개 코드 링크는 `main/server`를 가리킨다. GitHub 반영에 필요한 파일 목록의 내용 확인값도 갱신했다. 이번 변경은 안내에 필요한 7개 파일만 공개 저장소에 올렸다.

　실제 공개 `server/README.md`를 다시 읽어 고정 버전 링크가 없는지와 Git 내려받기 명령이 `main`을 지정하는지 확인했다. 원고 9개의 흐름, 명령어가 가리키는 파일 49곳, 게시용 HTML의 링크와 사진 위치도 확인했다. 공개 사진에 숨은 개인정보는 없었다. 코드 실행 방식은 바꾸지 않은 안내 변경이라 기능 테스트를 다시 돌리지는 않았다.

　바탕화면의 게시용 ZIP도 같은 링크로 갱신했다. 예전 버전 기록과 실제 프로그램 버전은 유지했다. 실행 출력은 터미널 기록 375의 TXT와 PNG로 남겼다.
