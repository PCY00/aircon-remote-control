# 2026-10-04 H2 대시보드 현장 시험

- 범위: Pi 대시보드에서 H2 연결 에어컨에 Zigbee IR 명령을 보내고 로그·실물 반응을 대조. 이번 기록은 문서화만 수행했고 Pi 설정·펌웨어를 다시 변경하지 않았다.
- 앞선 단계: GPIO5 IR 카메라 발광, USB 콘솔 `POWER_OFF` 실물 꺼짐 1회, Zigbee 일회성 MQTT `POWER_OFF` 실물 꺼짐 1회는 각각 별도로 확인돼 있었다. 기본 명령 확장 펌웨어와 대시보드는 배포됐지만 새 명령의 실물 반응은 당시 미확인이었다.
- 실패: 대시보드에서 `h2 result timed out. IR may have been sent. Check the appliance before retrying`가 표시된 시험이 있었다. 웹 명령 로그는 HTTP 502였고 Zigbee2MQTT에는 `MAC_CHANNEL_ACCESS_FAILURE`, `MAC_NO_ACK`가 기록됐다. 사용자는 오류가 난 명령에는 에어컨이 반응하지 않았다고 확인했다.
- 복구 관찰: 전원 연결과 기기 위치를 바꾸면서 H2가 여러 번 `device_announce`로 다시 나타났다. PC의 데이터 USB 연결에서 새 `COOL_STATE` 요청에 `accepted`·`sent`가 나왔다. 같은 5 V 3 A 충전기에 데이터 케이블을 연결한 조건에서도 00:44:31, 00:44:41 KST 새 요청에 HTTP 200과 `accepted`·`sent`가 기록됐다.
- 충전 전용 케이블 조건에서는 00:46:12, 00:48:30 KST 명령이 HTTP 502로 실패했으나, 재접속 뒤 00:48:41, 00:48:49, 00:48:54 KST 새 요청은 HTTP 200과 `accepted`·`sent`로 끝났다. 사용자는 성공 응답을 받은 송신마다 실제 에어컨이 반응했다고 확인했다. 따라서 데이터 케이블만 동작한다고 결론 낼 수 없다.
- 로그 해석: `device_announce` 직후 기존 `ir_result=sent`가 다시 게시된 것은 새 송신으로 세지 않았다. 실제 새 요청의 `accepted`와 `sent`를 구별해 기록했다. `sent`는 H2의 IR 송신 완료 보고이며 에어컨 상태를 직접 읽은 값은 아니다. 물리적 반응은 별도 사용자 관찰이다.
- 원인 판단: 전원 공급, 케이블, Zigbee 동글과의 거리, 재접속 시점이 함께 변했다. 무선 경로·재가입 문제가 의심되지만 단독 원인은 미확정이다. 가까이에서 접속 후 이동하는 방식의 거리 한계도 아직 측정하지 않았다. 한 번의 성공으로 장시간 신뢰성을 주장하지 않는다.
- 완료 범위: Step 4 시제품에서 Zigbee 명령을 대시보드로 보내 IR로 실제 에어컨을 조작하는 핵심 경로를 확인했다. 자동·제습·송풍·부가 기능 전체, 냉방 21–30°C 추론 프레임, 장기 RF 안정성, 배터리 운용은 별도 검증이 필요하다.
