# 2026-09-07 — 화면 모드 정리와 센서 부분 렌더링 최적화

## 요구사항

- PC 화면은 최대 1920×1080 기준으로 사용한다.
- 휴대폰·PC 선택은 운영 홈 상단이 아니라 `더보기`에서 관리한다.
- 색상 선택도 `더보기`에만 두고 디자인 검토용 `따뜻한 A · 장면 먼저` 배지를 제거한다.
- 센서 갱신 때 화면 전체를 다시 만들지 않고 실제로 달라진 부분만 반영한다.

## 화면 구조 변경

운영 화면 상단의 디자인 도구 모음을 완전히 제거했다. `더보기 → 화면`에는 라이트·다크
테마와 `자동·휴대폰·PC` 화면 구성을 함께 배치했다. 화면 구성은 브라우저 로컬 저장소에
보존한다. `자동`은 900px 이상에서 PC, 그 미만에서 휴대폰 레이아웃을 적용하며 화면 폭이
바뀌면 즉시 다시 계산한다.

PC 앱 셸은 최대 1920×1080을 기준으로 한다. 좌측 내비게이션 폭과 터치 영역을 키우고 홈은
빠른 장면·집 상태와 공간·기기 영역을 나눈 2열 구조로 배치했다. 작은 PC에서는 뷰포트 폭을
넘지 않으며 휴대폰 강제 모드는 기존 430px 단일 열과 하단 내비게이션을 유지한다.

## 렌더링 병목과 수정

기존 `refreshSensors()`는 매번 센서 카드 전체를 `replaceChildren()`으로 지우고 새로 만들며,
장치 카드 아이콘과 상세 정보도 다시 생성했다. 이어서 Lucide가 페이지 전체 아이콘을 다시
SVG로 바꿨고 모든 도어 센서의 최근 이력도 매번 요청했다.

수정 후에는 다음 원칙을 사용한다.

- `device_id`로 기존 센서 카드와 기기 카드를 찾아 같은 DOM 노드를 유지
- 텍스트가 실제로 달라진 경우에만 `textContent` 변경
- 아이콘이 새로 생기거나 종류가 바뀐 경우에만 Lucide 변환 실행
- 센서 상세 정보 행은 위치별로 재사용하고 달라진 값만 변경
- 도어 이력은 최초 로드, `last_changed_at` 변경 또는 열린 상세 화면의 수동 갱신 때만 요청
- 센서 관리 목록은 기기 ID와 사용자 메타데이터 서명이 달라진 경우에만 재구성
- 카드에 CSS containment를 적용해 레이아웃·페인트 영향 범위를 제한

## 검증 중 이슈

처음 `python -m pytest`와 `python -m ruff`를 실행했을 때 Windows 전역 Python이 선택돼
FastAPI와 Ruff를 찾지 못했다. 코드 결함이 아니라 실행 환경 문제였고 프로젝트
`.venv/Scripts/python.exe`를 명시해 다시 검사했다.

- 전체 테스트: 64개 통과
- Ruff: 통과
- `node --check app/static/sensors.js`: 통과
- `git diff --check`: 통과
- Edge headless 1920×1080 실제 렌더: 좌측 내비게이션과 2열 홈 확인
- 저장한 PNG의 비공개 메타데이터: 0건

## Raspberry Pi 배포

사용자 사전 승인 후 런타임 파일 두 개만 전송했다.

```text
app/static/index.html
app/static/sensors.js
```

대상은 `/home/air/aircon-controller/app/static/`이며 삭제 동기화나 데이터베이스 변경은 하지
않았다. 전송 뒤 로컬·원격 SHA-256 일치, 8001 루트 응답의 화면 모드 세 항목과 제거된 디자인
배지를 확인했다. Chromium이 같은 정적 JavaScript URL의 디스크 캐시를 재사용하지 않도록
`sensors.js` 참조에 배포 버전을 붙였다. 새 페이지를 즉시 로드하기 위해
`aircon-kiosk.service`만 재시작했다.

최종 상태는 키오스크 active, 재시작 0회, `wayland-0` 존재, Chromium 실행, Tailscale health
200이다. 이전 전송에서 생긴 프로젝트 루트의 비활성 사본 3개는 이번 UI 승인 범위와 무관해
건드리지 않았다.
