# 2026-10-04 ESP32-H2 기본 명령 확장

- 요청: H2 펌웨어에 기본 기능을 넣고 Raspberry Pi 대시보드에서 시험할 수 있게 준비.
- 로컬 기준본: `firmware/esp32-h2-zigbee-ir-node/`, Carrier CS-A061GS 명령 프로필, Zigbee2MQTT 외부 변환기, 웹/API.
- 기존 v1 `POWER_OFF`는 유지. 새 v2 패킷은 냉방 온도·풍량과 자동/제습/송풍/절전/터보/LED/풍향 고정/스윙 명령을 전달. 요청 ID·명령을 응답과 대조하고 자동 재전송하지 않음.
- 고정 IR 프레임은 저장된 캡처 자료에서 옮김. 17–20°C 냉방은 측정값 기반, 21–30°C는 프로필의 Gray-code 규칙을 적용한 추정값. LED의 실제 효과는 미확인.
- 검증: 펌웨어 빌드 성공(511168바이트), 호스트 프로토콜·프레임 테스트 성공. 고정 명령 9종과 냉방 17–30°C × 풍량 4종(합계 65개 조합)의 프레임·반복 횟수를 `commands.json`과 대조. Python 210 통과·2 건너뜀, Node 28 통과, 변환기 구문 검사 통과.
- 보드: COM6의 ESP32-H2와 플래시 크기를 확인. 업데이트 전 전체 4 MB 플래시를 저장소 밖에 비공개 백업하고 파티션 테이블을 대조. 애플리케이션 영역만 업데이트했으며 NVS/가입 정보는 보존. 기존 Zigbee 네트워크 재등장 확인. 이때 IR 명령은 보내지 않음.
- Pi: 다섯 파일을 미리보기 후 단방향 전송해 SHA-256 일치 확인. 런타임 외부 변환기의 기존 해시가 예상 값과 같은지 확인하고 비공개 백업 후 교체. Zigbee2MQTT 재시작 뒤 변환기 로드와 기존 센서·H2 등록 유지 확인. 웹 서비스 재시작은 열린 연결 종료 때문에 지연됐지만 `active`와 `/health` 응답을 확인. H2 `supported=true`, 인터뷰 성공, 기존 에어컨 연결 유지 확인.
- 마무리: 설치 도구의 서식 정리와 화면의 오래된 ‘끄기만 지원’ 안내를 각각 단일 파일로 재전송. 풍향 버튼도 움직임에는 `swing_toggle`, 고정에는 `airflow_fix`를 보내도록 수정해 마지막 화면 파일을 재전송. 화면은 별도 재시작 없이 응답 SHA-256과 Pi 파일 SHA-256이 일치함을 확인.
- 관찰: Zigbee2MQTT 재시작 시 과거 `POWER_OFF` 결과가 같은 요청 ID로 다시 게시됐다. 새 명령/새 IR 송신으로 해석하지 않음. 웹은 현재 대기 중인 요청 ID·명령이 일치할 때만 완료로 처리.
- 미검증: 새 냉방·모드·부가 기능의 실제 에어컨 반응, 웹 버튼을 통한 물리적 끄기 재검증. `sent`는 RMT 송신 완료이지 에어컨 상태 센서값이 아님.
- 블로그 자료: `docs/assets/terminal/363-h2-basic-command-local-checks.*`, `364-h2-basic-command-pi-deployment.*`. 이미지 검사 `PRIVATE_METADATA_COUNT=0`.

이후 대시보드 현장 시험에서 냉방 상태 명령의 실물 반응을 확인했다. 배포 직후의
미검증 상태와 후속 결과는 [별도 현장 시험 일지](2026-10-04-h2-dashboard-field-test.md)로
구분해 기록한다.
