# 스마트홈 알림 — 2026-10-13

## 전체 코드에서 문제를 찾아 고쳤다

　저장소 전체 코드를 다시 읽고 문제 있는 곳을 찾아 고치자고 했다. Pi 웹앱(IR·기기·센서·자동화), 키오스크 화면, ESP32-H2 펌웨어, A50 중앙 서버, Pi 연결 서비스, 가족 앱, A50 관리 도구, 블로그·배포 스크립트, PCB 생성 도구까지 10개 영역으로 나눠 읽었다. 영역마다 찾은 문제를 다른 확인 담당이 실제 코드를 돌려 보며 반박해 봤다. 처음에는 세션 사용 한도에 걸려 10개 작업이 중간에 멈췄고, 한도가 풀린 뒤 끝난 결과는 그대로 두고 멈춘 작업만 다시 돌렸다.

　보고된 73건 가운데 69건이 실제 문제로 확인됐고 4건은 일어날 수 없는 상황이거나 문서로 정한 설계였다. 확인 중에 3건이 더 나왔다. 가장 큰 문제는 세 가지였다. 첫째, 냉방 온도를 Gray 코드 공식으로 만들고 있었는데 17~20℃만 실측한 공식이라 27℃·28℃에서 Coolix 온도표와 달랐다. 28℃는 송풍 전용 값이 나가고 있었다. 둘째, 경제운전(앱의 절전)이 녹화 당시의 ‘냉방 17℃ 자동풍’ 프레임까지 그대로 보내서, 26℃로 쓰다가 누르면 17℃로 내려가고 꺼져 있으면 켜졌다. 화면과 서버에는 이전 상태가 남았다. 셋째, H2가 Zigbee 접속에 실패하면 다시 시도하지 않았다. 10월 11일 기록의 `0x03; reboot to retry`가 바로 이 경우였다.

　경제운전은 실제 리모컨처럼 경제운전 신호를 한 번 보낸 뒤 지금 냉방 온도에 바람 자동 상태를 두 번 보내도록 바꾸자고 정했다. 냉방 중이 아니면 보내지 않고 거부한다. H2 경로에서는 Pi가 `ECONOMY`를 보낸 뒤 `COOL_STATE`를 이어 보낸다. 확인된 문제는 전부 고치기로 했다.

## 고친 것

　27℃·28℃는 Pi(`commands.json`, 명령 생성 코드)와 H2 펌웨어(`carrier_profile.h`)를 모두 Coolix 온도표로 바꿨다. 27℃는 `90 6f`, 28℃는 `80 7f`가 나가는지 테스트로 확인했다. Pi와 펌웨어가 만드는 프레임이 온도·바람 세기 전부에서 같은지도 테스트로 맞춰 봤다.

　그 밖에 바꾼 것은 다음과 같다.

- Pi 연결 서비스: 알림 원본 DB에 문제가 생겨도 에어컨 제어 확인과 연결 신호는 계속 보내게 했다. 결과 보고가 거절돼도 제어가 10분 동안 멈추지 않게 했다. 지원하지 않는 명령이나 알리지 않은 기기 ID는 IR을 보내지 않고 실패로 알린다. Pi 앱이 4xx로 거절한 명령은 ‘실패’, 보냈는지 모르는 경우는 ‘알 수 없음’으로 나누고 다시 보내지 않는다.
- 가족 앱: 화면을 돌리거나 다크모드가 바뀌어도 에어컨 조작 화면과 고르던 설정이 남게 했다. 결과를 기다리는 동안 화면 전체가 멈추지 않게 했고, 빠르게 두 번 눌러도 한 번만 보내게 했다. 절전 확인 문구에 ‘냉방 중에만 작동하고 바람이 자동으로 바뀐다’는 설명을 넣었다.
- 키오스크 화면: 다른 곳(가족 앱)에서 바꾼 상태를 실시간으로 받아 반영하게 했다. 장면·방·집 이름을 브라우저에 저장하게 했고, 새 모델 분석 요청이 선택 파일 없이도 되게 했다.
- Pi 웹앱: 이름을 바꾸거나 지운 문 센서가 ‘문 열림’ 경고를 계속 띄우지 않게 했고, 센서 삭제 API를 만들었다. IR 녹화 분석이 실패해도 수신기가 ‘사용 중’으로 남지 않게 했다. 수신 장치를 `/dev/lirc1`로 맞췄다.
- 중앙 서버: 명령 남은 시간이 0 이하로 계산되지 않게 했다. Google 인증서를 잠깐 못 받아도 바로 503이 되지 않게 했다.
- H2 펌웨어: Zigbee 접속 실패나 네트워크에서 빠졌을 때 1초부터 60초까지 늘려 가며 다시 접속하게 했다. 새 펌웨어임을 알 수 있게 `capability` 값을 2로 올렸다.
- A50 도구: `install_a50_manager.py --apply`가 `adb.json`의 SSH 복구 설정을 꺼버리던 문제를 고쳤다. Android 8.0에서 관리 앱이 바로 꺼지던 문제도 고쳤다.
- 블로그 사진 검사: PNG 안의 C2PA 메타데이터를 놓치던 검사를 허용 목록 방식으로 바꿨다. 실제로 걸린 사진 1장(`esp32-h2-supermini-user-wiring-gpio5-edited.png`)은 메타데이터만 지웠고 화면은 그대로다. 이미 확인한 동영상은 해시와 함께 `docs/assets/.sanitize-reviewed.json`에 적어 두어 기존 검사 명령이 그대로 통과한다.

　고친 뒤 다른 담당이 바뀐 코드만 다시 읽어 봤다. 키오스크에서 방 이름을 바꿔도 실시간 반영 때문에 원래대로 돌아가는 문제, H2 경제운전 두 단계가 합쳐서 최대 36초까지 걸리는 문제, 티스토리 출력 정리가 사용자가 고른 폴더의 `사진` 폴더까지 지울 수 있는 문제 등이 나왔다. 모두 고쳤다.

## 바뀐 부분과 배포 전에 막힌 곳을 확인했다

　서버 자동 확인 327개가 통과했고 2개는 Windows에서 실행하지 않는 항목이라 건너뛰었다. 루트에서는 177개가 통과하고 배포 도구 확인 1개가 실패했다. 비대화형 PowerShell에서 `Get-FileHash`를 찾지 못하는 문제가 다시 나타났다. 파일 해시를 .NET의 SHA-256으로 직접 계산하도록 바꿨고 배포 도구 관련 5개 확인이 통과했다. 화면·센서·Zigbee 변환기 확인 54개도 통과했다.

　Pi의 현재 코드와 Git 기준본을 비교했더니 센서 관련 코드·예시 설정·IR 설명 5곳에 더 이전 내용이 남아 있었다. 현재 수정본과 차이를 읽고 원본을 비공개로 보관했다. 실제 수신 장치가 `/dev/lirc1`, 송신 장치가 `/dev/lirc0`인 것도 읽어서 확인했다. 배포할 Pi 파일은 18개로 제한했고 센서 기록이나 비밀 설정을 복사 대상으로 넣지 않았다.

　A50 중앙 서버는 저장 파일을 백업한 뒤 수정본으로 바꿨다. 정상 응답과 코드 파일 일치를 확인했다. Pi는 데이터 백업 단계에서 SQLite가 아닌 `.db` 파일까지 SQLite로 읽으려 해 멈췄다. 이때는 웹 서비스를 아직 멈추거나 프로그램을 덮어쓰기 전이었다. 파일의 실제 형식을 먼저 읽고 SQLite는 일관된 백업을 만들며 다른 형식은 원래 바이트 그대로 보관하도록 바꿨다.

　앱에도 바뀐 코드가 있음을 이전 APK를 만들 때 사용한 소스와 비교해 확인했다. 혼동하지 않도록 앱 버전을 0.5.2로 올리고 개발용·배포용 APK를 만들었다. 기존 서명·HTTPS 사용·시험용 자료 제외도 확인했다. Pi 반영과 전체 연결 확인은 계속 진행 중이다.

## Pi와 A50에 수정본을 반영하고 다시 연결했다

　Pi 웹앱·기기 프로필·실행 설정 18개 파일을 반영했다. 원래 파일과 실행 설정을 보관하고 SQLite 저장 파일 6개를 일관된 상태로 백업했다. SQLite가 아닌 파일 2개도 원래 내용 그대로 보관했다. 바뀐 파일과 실제 실행 중인 서비스 설정이 로컬과 같은지 마지막으로 비교했다. 웹 서비스의 종료 대기는 20초로 설정됐다.

　A50 중앙 서버와 HTTPS 통로, Pi 연결 서비스도 수정본으로 바꿨다. 중앙 서버 버전 표시는 0.5.1이고 소스 묶음은 새 내용이며 저장소 스키마는 5를 유지했다. 기존 집·가족·허브 등록은 남아 있었다. 중앙 서버의 정상 응답, 저장 파일 상태, 로그인 없는 요청의 거절을 확인했다. Pi에서는 센서 2개와 MQTT 연결, 화면의 새 파일 버전, 실시간 연결의 준비·연결 유지 신호를 확인했다. 가입 허용은 꺼진 상태였다.

　HTTPS 통로를 다시 시작해 임시 주소가 바뀌었다. Pi는 새 주소로 연결하고 기존 허브 키는 유지했다. 중앙 서버가 Pi와 에어컨 1대를 다시 읽는 것까지 확인했다. 실제 운영 주소는 공개 일기나 저장소에 적지 않고 사용자에게 전달할 비공개 안내 파일에만 남겼다. 사용자 휴대폰의 앱 연결 설정에도 새 주소를 저장해야 한다.

　최종 자동 확인은 루트 178개, 서버 327개(2개 건너뜀), 화면·변환기 54개, 가족 앱 22개가 통과했다. 배포 도구 오류를 고친 뒤 루트 전체도 다시 실행해 모두 통과한 결과를 받았다. 가족 앱 0.5.2 APK를 기존과 같은 서명으로 만들고 바탕화면에 저장한 뒤 원본과 같은 파일인지 확인했다. 예전 APK는 지우지 않았다.

　H2 펌웨어 소스에도 27·28°C 온도표와 재접속 수정이 들어 있지만 보드에는 이번에 쓰지 않았다. 앞서 0.5.1의 명령 연결에는 펌웨어 변경이 필요 없었으나, 이번 신호 오류 수정은 H2에도 별도 반영해야 한다. 현재 H2 경로의 27·28°C 신호가 새 코드로 고쳐졌다고 표시하지 않았다. 실제 에어컨 명령은 보내지 않았고 새 APK의 실기기 화면과 에어컨 반응 확인은 남아 있다.

## 주소를 고정하는 방법과 저렴한 도메인을 찾아봤다

　사용자가 주소가 바뀌지 않으려면 도메인이 필요한지 물었다. [Cloudflare 공식 안내](https://developers.cloudflare.com/tunnel/get-started/)를 읽었다. 현재 임시 통로 대신 도메인을 연결한 정식 터널에 고정된 주소를 붙이는 방법을 설명했다. 서버는 A50을 그대로 사용할 수 있다. 도메인 구매와 DNS 변경, 정식 터널 전환은 아직 하지 않았다.

　저렴한 도메인도 찾아 달라고 했다. 첫해 할인과 갱신 가격을 구분했다. [.xyz 공식 안내](https://gen.xyz/1111b)에서는 숫자 6~9자리로 된 1.111B 종류를 매년 0.99달러로 안내했다. 실제 판매처의 결제·갱신 가격과 원하는 번호의 등록 가능 여부는 아직 확인하지 않았다고 구분했다. [Cloudflare 가격표](https://pricing.registrar.cloudflare.com/)의 일반 `.win`은 첫해 4.18달러, 갱신 5.18달러였다. 일반 글자 `.xyz` 가격과 숫자 전용 종류의 가격을 섞지 않았다. 앱에 저장할 서버 주소용이라면 숫자 `.xyz`를 먼저 볼 만하다고 설명했다.

## XYZ 구매 방법을 읽다가 도메인 선택을 바꿨다

　사용자가 숫자 `.xyz`를 어떻게 결제하는지 물었다. 공식 가격표에서 숫자 6~9자리 종류의 등록·갱신이 연 0.99달러임을 다시 읽었다. 브라우저에서 공식 구매 페이지를 열었지만 등록 입력 양식이 보이지 않았다. 메인 검색과 다른 판매처의 예시 숫자 검색도 해봤으나 실제 등록 가능 여부나 그 도메인의 결제 금액까지 확인하지는 못했다. 판매처의 공식 구매 절차와 카드·PayPal 결제 안내를 읽는 단계였다. 계정을 만들거나 결제 정보·개인정보를 입력하지 않았다.

　이어서 사용자가 `.xyz`보다 비용을 조금 더 내더라도 믿을 만한 곳에서 1년 동안 쓰자고 했다. XYZ 구매 확인을 멈추고 공식 판매처에서 `.com`을 등록하는 방향으로 바꿨다. 이 선택은 사용자의 선호에 따른 것이며 `.xyz`나 해당 판매처를 사기라고 확인한 것은 아니다.

　[Cloudflare 공식 도메인 서비스](https://www.cloudflare.com/domains/)와 [가격표](https://pricing.registrar.cloudflare.com/)를 읽었다. 일반 `.com`의 현재 1년 등록·갱신 가격은 각각 10.46달러였다. 특정 이름의 등록 가능 여부와 최종 결제 금액은 아직 확인 전이다. 원하는 영문 이름을 물었고 답을 기다리고 있다. 공식 판매처에서 도메인과 고정 주소 연결을 함께 관리하는 방법을 제안했다. 도메인 구매나 DNS·서버 설정 변경은 하지 않았다.

## 5천 원 예산에 맞춰 도메인 이름을 골라봤다

　사용자가 도메인 이름을 추천해 달라고 했고 되도록 1년에 5천 원 이하였으면 한다고 했다. 앞서 원하지 않는다고 한 `.xyz`는 후보에서 뺐다. 첫해 할인과 다음 해 연장 비용을 나눠서 공식 판매처를 찾아봤다.

　[호스팅케이알 도메인 검색](https://www.hosting.kr/domain/search)에서 `roomrelay.cloud`, `myroomhub.cloud`, `roomping.cloud`를 실제로 검색했다. 세 이름 모두 장바구니에 담을 수 있는 상태였고 첫해 1년 가격은 각각 2,700원으로 표시됐다. ‘방의 소식을 전달한다’는 뜻으로 `roomrelay.cloud`를 첫 번째 후보로 골랐다. 이름이 등록 가능한 상태는 검색한 시점 기준이며 아직 구매하지 않았다.

　전체 도메인 가격표에서는 `.cloud`의 신규 등록 행사 가격이 2,700원, 기간 연장이 40,000원이었다. 공식 요금 공지에는 부가세 별도라고 되어 있다. 부가세 10%를 더해 계산하면 첫해는 2,970원, 현재 연장 요금은 44,000원이다. 실제 결제 화면의 총액은 아직 확인하지 않았다. 첫해만 예산 안에 들고 다음 해에도 5천 원 이하로 유지되는 상품은 아니라고 구분했다. 1년 시험용으로는 후보가 되지만 계속 저렴하게 쓸 목적에는 맞지 않는다.

　검색 결과 화면을 `server/docs/assets/domain/2026-10-13-cloud-domain-candidates.jpg`에 남겼고 공개하면 안 되는 사진 정보가 없는지 확인했다. 개인정보 입력·장바구니 추가·결제·DNS 변경·서버 설정 변경은 하지 않았다. 이름 선택과 실제 구매, 고정 주소 연결은 남아 있다.

## 다음 해에도 저렴하게 갱신할 도메인으로 다시 골랐다

　사용자가 첫해만 싼 도메인은 안 되고 다음 해에도 저렴하게 유지되는 것으로 골라 달라고 했다. 앞서 제안한 `.cloud`는 후보에서 뺐다. `.xyz`를 원하지 않는다는 조건도 유지했다. 이번에는 갱신 가격을 먼저 읽었다.

　Cloudflare 공식 가격표에서는 `.win` 갱신이 5.18달러, `.uk`는 5.30달러였다. OVHcloud의 `.ovh`는 비교 사이트에 저렴한 가격이 있었지만 공식 화면에서 현재 신규 등록 상품을 확인하지 못해 추천에 넣지 않았다. [Spaceship의 `.top` 공식 안내](https://www.spaceship.com/domains/gtld/top/)와 실제 가격표를 읽었다. 등록은 1.40달러, 갱신은 3.85달러였고 실제 가격표에는 매년 ICANN 수수료 0.20달러가 따로 표시됐다. 수수료까지 포함한 현재 금액은 첫해 1.60달러, 갱신 4.05달러였다.

　Spaceship에서 `roomrelay.top`을 직접 검색해 등록 가능하다는 표시를 확인했다. 첫해와 갱신 가격, 추가 수수료가 함께 보이는 화면도 남겼다. [Wise 환율 안내](https://wise.com/us/currency-converter/usd-to-krw-rate/history/30-09-2026)의 1달러 약 1,337.55원으로 계산하면 첫해 약 2,100원, 다음 해 약 5,400원이다. 세금과 카드 수수료, 실제 결제 환율은 별도라 매년 5천 원 이하라고 말하지 않았다. 현재 확인한 후보에서는 예산을 조금 넘기는 `.top`이 저렴하게 계속 갱신할 수 있는 선택이었다.

　연장하면 같은 주소를 유지할 수 있지만 지금 표시된 갱신 가격이 영구히 고정되는 것은 아니라고 구분했다. 아직 이름을 구매하거나 자동 갱신을 설정하지 않았다. 계정 생성·개인정보 입력·결제·DNS 변경·서버 변경도 하지 않았다. 이름 선택과 실제 구매, 고정 주소 연결은 남아 있다.

　사진은 `server/docs/assets/domain/2026-10-13-top-domain-available.jpg`와 `server/docs/assets/domain/2026-10-13-top-domain-renewal-price.jpg`에 저장했다. 이 폴더의 사진 3장에 공개하면 안 되는 메타데이터가 없는 것을 확인했다.

## 도메인을 정하고 결제 순서를 확인했다

　사용자가 `roomrelay.top`으로 정했고 어디서 어떻게 결제하면 되는지 물었다. Spaceship의 실제 검색 화면에서 이 도메인 하나만 장바구니에 담았다. 추가 상품을 권하는 창에서 Spacemail·웹호스팅·사이트 제작·VPS 등의 무료 체험을 선택하지 않고 `Continue to cart`로 넘어갔다. 무료 체험 뒤에는 매월 비용이 생기는 상품이라 도메인 결제와 구분해 안내하기로 했다.

　장바구니에는 등록 기간 `1 year`, 무료 개인정보 보호가 표시됐다. 도메인 1.40달러와 ICANN 수수료 0.20달러를 합한 현재 장바구니 금액은 1.60달러였다. 도메인 자체의 다음 해 연장은 3.85달러였고 ICANN 수수료를 더한 현재 기준 갱신 합계는 4.05달러다. 로그인 뒤 주소와 결제 수단에 따라 붙는 세금·환전·카드 수수료까지 확인한 최종 청구 금액은 아니다.

　`Checkout`을 누르니 로그인 창과 `Sign up` 버튼이 나왔다. 사용자에게 공식 검색 링크부터 장바구니·1년 선택·계정 가입 또는 로그인·본인 정보 입력·카드나 PayPal 결제 순서를 안내했다. 자동 갱신을 켜면 다음 갱신 때 자동으로 결제되는 선택임을 설명하고 사용자가 결정하도록 했다. 소유자 확인 이메일이 오면 그 안내도 완료해야 한다.

　계정을 만들거나 비밀번호·연락처·카드 정보를 입력하지 않았다. 결제도 하지 않았고 도메인을 소유한 상태라고 표시하지 않았다. 구매 확인 뒤 Cloudflare에 고정 주소를 연결하는 작업은 남아 있다. 장바구니 화면은 `server/docs/assets/domain/2026-10-13-roomrelay-top-cart.jpg`에 저장했다.
