# H2를 스마트홈 Zigbee IR 프로그램으로 다시 바꿨다

　사용자가 가족 앱 업데이트 설치 전에 H2 펌웨어부터 다시 올려 달라고 했다. 실제 USB 포트를 읽어 ESP32-H2와 4 MB 플래시를 확인했다. `firmware/esp32-h2-zigbee-ir-node/`의 현재 코드로 빌드를 끝냈고 프로그램 크기는 511,168바이트였다.

　플래시 전체를 저장소 밖에 비공개로 백업하고 현재 저장 공간 배치를 읽었다. 기존 프로그램 위치는 `0x10000`으로 기본 Zigbee 빌드의 `0x20000`과 달랐다. 첫 시도는 파티션 비교에서 멈췄고 쓰기 명령은 실행하지 않았다. 기존 프로그램을 다시 실행한 뒤 USB 출력에서 G V2 수동 시험 프로그램이 들어 있음을 확인했다. 임의로 덮어쓰지 않고 사용자에게 확인했고 스마트홈 에어컨용 Zigbee IR이라는 답을 받았다.

　기존 저장 공간 배치와 NVS 설정 영역을 유지하고 실제 프로그램 파티션인 `0x10000`에 프로그램만 다시 썼다. 부팅 프로그램·파티션 표·NVS를 덮어쓰거나 플래시 전체를 지우지 않았다. 쓰기 후 다시 읽은 프로그램이 빌드 파일과 정확히 같았다. 쓰기 전후 4 MB 전체를 비교해 프로그램이 차지하는 플래시 섹터 밖의 바이트가 모두 같은지도 확인했다. 이 보드에는 `0x20000`을 그대로 복사해 쓰면 안 된다. 다음 업데이트도 실제 파티션 표부터 읽어야 한다.

　새 프로그램의 시작과 GPIO5 준비를 확인했다. 첫 실행에서는 Zigbee 초기화에 `0x03` 오류가 나왔다. USB 보드와 Pi의 기존 H2가 같은 기기인지 식별값을 비공개로 비교했고 같았다. 기존 등록을 지우거나 NVS를 초기화하지 않았다.

　사용자가 최대 120초의 가입 허용을 승인했다. 가입 허용을 연 직후 USB 연결이 사라져 PC에서 다시 켜지 못했다. 사용자가 다른 전원과 위치로 옮겼다고 알려줬다. 닫기 첫 시도는 이미 가입이 열려 있으면 멈추는 사전 조건 때문에 실행되지 않았다. 닫기만 수행하는 방법으로 바꾸고 Pi에서 가입 허용이 꺼진 상태를 실제로 읽어 확인했다. 이후 사용자가 연결됐다고 했고 Pi의 최근 기록에서도 같은 H2의 재등장 1건과 지원 상태를 확인했다. 가입 허용은 꺼져 있었다. 이 기록은 무선 재등장 확인이며 실제 IR 송신 성공을 뜻하지 않는다.

　PC용 USB IR C 시험에서는 실제 코드가 쓰는 GPIO5가 시험용 이름 목록에 없어 7개가 컴파일되지 않았다. 시험용 이름을 추가하고 다시 실행해 Zigbee 명령·프레임과 USB IR 코드의 9개 확인을 통과했다. 실제 펌웨어와 배선은 바꾸지 않았다. 새 빌드 결과도 이전에 올린 프로그램과 같은 파일 크기였다.

　실제 에어컨 명령은 보내지 않았다. H2에는 기존 온도·풍량·모드·풍향·부가 명령이 들어 있으므로 가족 앱에 이 명령을 연결하기 위해 펌웨어를 다시 올릴 필요는 없다. 전체 명령의 실물 반응은 별도 확인이 필요하다.
