# 2026-10-02 — A50 중앙 API 외부 HTTPS 연결

요청: 다른 휴대폰에서 사용할 중앙서버 HTTPS 주소 생성. 사용자는 A50을 직접 조작할 수 없다.
도메인은 없다고 답했다. Cloudflare Quick Tunnel 시험 주소를 선택했다.
이 기록에는 실제 접속 URL·기기 주소·Cloudflare 연결 식별자를 남기지 않는다.

## 진행과 검증

- 읽기 전용 확인: A50 aarch64, cloudflared 미설치, 전용 서비스 경로 미사용.
- 공식 Cloudflare·Termux 자료 확인, apt 시뮬레이션에서 기존 업그레이드 없이 패키지 1개 추가.
- cloudflared 2026.9.3-1 설치, 패키지 기본 서비스의 down 유지·중앙 readiness 정상(199).
- 로컬 실패: Windows `os.O_NONBLOCK` 부재로 2개 검사 실패와 Ruff 지적(200).
  POSIX 전용 FIFO 통신의 플랫폼 예외와 코드 형식을 수정했고 7개 검사/Ruff 통과(201).
- 체크섬 소스 4개와 별도 서비스 배포를 미리보기로 확인(202).
- 첫 실제 배포: runit이 새 폴더를 스캔하기 전 `sv-enable`이 실행되어
  `unable to open supervise/ok: file does not exist`(203).
  이후 서비스가 인식되어 연결됐음을 읽기 전용으로 확인했다.
- 새 서비스 인식 대기를 추가하고 재배포. 정상 중지·재시작과 소스/훅 체크섬 일치(204).
  기존 중앙 API를 중지하지 않았고 사용자 데이터·관리 SSH·공유기를 변경하지 않았다.
- 외부 HTTPS 시스템 인증서 검증·ready 200·인증 없음/위조 401·no-store 통과(205).
- 추가 읽기 전용 검증에서 중앙 소스·DB 식별자·SSH 훅 보존, 사용자/집/허브 0개 확인(206).
- 실제 외부 HTTPS 준비 페이지를 in-app browser에서 열고 캡처했다.
  페이지에 보이는 “정상 동작 중”은 준비 상태이며 실제 사용자 인증 성공 화면이 아니다.

## 현재와 다음

임시 주소는 사용자에게 직접 전달하고 앱 저장 후 집 목록/오류 여부를 요청했다.
실제 주소는 `.deploy/a50/tunnel-endpoint.json`과 장비 상태 디렉터리에서만 관리한다.
사용자의 앱 결과는 아직 기다리고 있다. 시험 URL은 터널 프로세스 재시작 때 바뀐다.
부팅 후 실행 구조는 구성했지만 이번 단계의 실제 기기 재부팅·장시간 시험은 하지 않았다.
고정 도메인·FCM·실제 Pi 연결도 남아 있다.
