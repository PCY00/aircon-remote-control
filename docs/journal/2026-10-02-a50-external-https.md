# 2026-10-02 — A50 중앙 API 외부 HTTPS 연결

요청: 다른 휴대폰에서 사용할 중앙서버 HTTPS 주소 생성. 사용자는 A50을 직접 조작할 수 없다.
도메인은 없다고 답했다. Cloudflare Quick Tunnel 시험 주소를 선택했다.
이 기록에는 실제 접속 URL·기기 주소·Cloudflare 연결 식별자를 남기지 않는다.

## 진행과 검증

- 읽기 전용 확인: A50 aarch64, cloudflared 미설치, 전용 서비스 경로 미사용.
- 공식 Cloudflare·Termux 자료 확인, apt 시뮬레이션에서 기존 업그레이드 없이 패키지 1개 추가.
- cloudflared 2026.9.3-1 설치, 패키지 기본 서비스의 down 유지·중앙 readiness 정상(199).
- 로컬 실패: Windows `os.O_NONBLOCK` 부재로 2개 검사 실패와 Ruff 지적(200).
  POSIX 전용 FIFO 통신의 플랫폼 예외와 코드 형식을 수정했고 7개 검사/Ruff 통과(201).
- 체크섬 소스 4개와 별도 서비스 배포를 미리보기로 확인(202).
- 첫 실제 배포: runit이 새 폴더를 스캔하기 전 `sv-enable`이 실행되어
  `unable to open supervise/ok: file does not exist`(203).
  이후 서비스가 인식되어 연결됐음을 읽기 전용으로 확인했다.
- 새 서비스 인식 대기를 추가하고 재배포. 정상 중지·재시작과 소스/훅 체크섬 일치(204).
  기존 중앙 API를 중지하지 않았고 사용자 데이터·관리 SSH·공유기를 변경하지 않았다.
- 외부 HTTPS 시스템 인증서 검증·ready 200·인증 없음/위조 401·no-store 통과(205).
- 추가 읽기 전용 검증에서 중앙 소스·DB 식별자·SSH 훅 보존, 사용자/집/허브 0개 확인(206).
- 실제 외부 HTTPS 준비 페이지를 in-app browser에서 열고 캡처했다.
  페이지에 보이는 “정상 동작 중”은 준비 상태이며 실제 사용자 인증 성공 화면이 아니다.

## 현재와 다음

임시 주소는 사용자에게 직접 전달하고 앱 저장 후 집 목록/오류 여부를 요청했다.
실제 주소는 `.deploy/a50/tunnel-endpoint.json`과 장비 상태 디렉터리에서만 관리한다.
사용자의 앱 결과는 아직 기다리고 있다. 시험 URL은 터널 프로세스 재시작 때 바뀐다.
부팅 후 실행 구조는 구성했지만 이번 단계의 실제 기기 재부팅·장시간 시험은 하지 않았다.
고정 도메인·FCM·실제 Pi 연결도 남아 있다.

## A50 실제 계정 시험을 위한 사용자 로그인 준비

사용자가 A50에 APK를 설치·시험해 달라고 요청했고, Google 로그인은 직접 하겠다고 했다.
검증된 배포 APK를 데이터 보존 `install -r`로 설치 Success, COLD 실행 527ms·로그인 UI 확인(208).
실제 로그인·집 등록까지 통과했다고 기록하지 않는다.
공식 scrcpy v4.1 ZIP 체크섬 확인·포터블 준비(209), 기존 검증된 ADB로 A50만 선택해
`A50 - Family Smart Home` 창의 실행을 확인했다(210).
음성·영상 녹화·클립보드 자동 동기화를 끄고 사용자 직접 로그인에 입력을 넘겼다.
자격 증명 입력 중에는 캡처하지 않는다. 실제 계정 추가·Google 로그인 결과는 아직 기다린다.

## 사용자 직접 로그인 후 실제 계정·배포 APK 시험 완료

사용자가 “로그인했어”라고 보고했고 A50의 실제 로그인 완료 화면을 확인했다.
현재 HTTPS 주소를 앱에 저장해 실제 Google 토큰으로 집 목록을 받았다(214).
사용자가 선택한 `A50 테스트 집`을 실제 앱 UI로 만들고 소유자/가족 관리 화면을 확인했다.
기존 다른 집 한 개는 보존했다. 실제 사용자 1명·집 2개·허브 0개다.

- 211: 빈 입력창 안내 문구를 기존 주소로 판단한 보호 검사가 멈췄다. 이때 주소·계정은 바뀌지 않았다.
- 212: 키보드 표시 후 이전 저장 버튼 좌표를 사용해 기대 화면 검사가 실패했다.
  새 UI 트리를 읽고 저장하도록 수정해 214에서 실제 집 목록을 확인했다.
- 215~216: 전용 production 검사 APK 빌드. 이전 배포 APK·해시 기록은 별도 경로로 보존한다.
- 217: Activity 실행 규칙 없이 시작한 검사는 집 목록을 기다리다 실패. 원래 MainActivity 실행 규칙 추가.
- 218~219: 집 생성·소유자 확인까지 진행했으나 검사 APK의 내부 파일 경로에 캡처를 쓰다 ENOENT.
  대상 앱의 외부 전용 파일 경로로 가린 캡처를 저장하도록 수정했다.
- 220~221: 최종 검사 APK 빌드·서명·정확한 대상 확인, 실제 설치된 release 해시 일치.
  이미 생성한 시험 집 재사용. **OK (1 test), 4.26초**, 집·소유자 가족 화면 캡처.
  원래 release 앱 재실행(COLD 354ms) 후 Google 세션·HTTPS 주소·집 목록 유지.
- 222: 실제 사용자 수를 허용하도록 읽기 전용 운영 검사 갱신. 사용자 발급자 일치·DB 무결성·
  런타임 식별자·기존 SSH 훅·서버 소스·백업 보존, 위조·인증 없는 요청 401 확인.
- 223: 시험 집 1개·활성 소유자 관계 1개·기존 다른 집 1개 확인. 홈 화면·화면 꺼짐 복원.
  사용자가 로그인한 Google 계정과 집을 보존했고, 노트북의 임시 미러링 프로세스만 종료했다.

이메일을 Android에서 가린 캡처만 공개 자료로 내보냈으며 비밀번호·토큰은 읽지 않았다.
실제 다른 계정의 초대/권한 회수·FCM·실제 Pi·고정 주소·기기 재부팅은 이번 시험 범위에 없다.
