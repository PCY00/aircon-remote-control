# 블로그 이미지 개인정보 메타데이터 점검과 제거

## 발견

블로그 게시 예정 자산을 점검한 결과 `docs/assets/hardware/`의 JPEG 25개 모두에 EXIF가
있었다. GPS 위도·경도 태그에는 0이 아닌 값이 있었고 촬영 시각, 카메라 제조사·모델과
MakerNote도 포함됐다. 실제 좌표값은 터미널과 문서에 출력하거나 기록하지 않았다.

Zigbee/MQTT와 기존 IR 블로그 본문에서 이미 참조 중인 하드웨어 JPEG 10개도 같은 영향을
받았다. 사진의 눈에 보이는 영역에는 개인 주소, 얼굴, 계정 또는 제품 고유 QR이 확인되지
않았다. 제품 모델·제조사·일반 배치 표기는 기술 자료로 유지한다.

터미널 PNG 39개에는 GPS가 없었다. 대응하는 TXT 원문도 확인했으며 사설 IP, Tailscale
주소, 비밀번호, MQTT 인증정보, Zigbee IEEE 주소와 동글 시리얼은 이미 제거 또는
`[REDACTED]` 처리되어 있었다. `air@AC`, `/home/air/aircon-controller`, 실행 날짜와 버전은
재현용 운영 정보로 남아 있으며 공개 전 필요하면 일반화할 수 있다.

## 원인

휴대폰으로 촬영한 JPEG 원본을 픽셀 내용만 확인하고 그대로 문서 자산 폴더에 복사했다.
EXIF는 사진 화면에는 보이지 않아 육안 검토만으로 발견할 수 없다. 블로그 플랫폼이 업로드
중 메타데이터를 제거할 수 있지만 서비스마다 동작이 달라 이를 보안 절차로 의존하면 안 된다.

## 해결

- Pillow로 EXIF orientation을 픽셀에 먼저 반영해 사진 방향을 보존한다.
- 새 이미지로 픽셀만 복사해 EXIF, GPS, XMP, 코멘트와 제조사 전용 APP 메타데이터를
  포함하지 않은 공개용 JPEG/PNG로 다시 저장한다.
- 임시 파일을 검증한 뒤 원본 경로를 교체한다.
- 기본 동작이 읽기 전용 검사인 `scripts/sanitize_blog_images.py`를 추가한다.
- `--apply`는 메타데이터가 발견된 파일만 변경하고 정리된 파일은 다시 인코딩하지 않는다.
- 이후 모든 블로그 자산은 게시 전에 검사 결과 `PRIVATE_METADATA_COUNT=0`을 요구한다.

## 검증 기준

- 공개 자산 전체에 EXIF/GPS/XMP/텍스트 위치정보가 없어야 한다.
- 모든 이미지가 정상적으로 열리고 기존 표시 방향과 해상도를 유지해야 한다.
- 터미널 PNG와 판매자 제공 PNG처럼 민감 메타데이터가 없는 파일은 변경하지 않아야 한다.
- 자동 테스트로 JPEG EXIF·orientation과 PNG 텍스트 메타데이터 제거를 재현한다.

## 실행 결과

- 전체 공개 자산 66개를 검사했다.
- 하드웨어 JPEG 25개를 정리했고 PNG 41개는 변경하지 않았다.
- 정리 후 전체 검사 결과 `PRIVATE_METADATA_COUNT=0`을 확인했다.
- 새 검사·정리 도구의 자동 테스트 3개와 Ruff 검사를 통과했다.
- JPEG의 EXIF orientation을 실제 픽셀 방향에 반영한 뒤 저장했으며 정리 후 파일 열기와
  해상도를 다시 확인했다.
