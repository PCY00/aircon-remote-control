# 2026-08-29 UI 설계 기록

## 확정한 방향

- 에어컨 전용 리모컨 화면이 아니라 여러 공간과 가전을 확장할 수 있는 스마트홈 플랫폼으로 설계한다.
- 홈은 `빠른 장면 → 공간 → 기기` 순서로 보여준다.
- 따뜻한 아이보리 배경, 옅은 파랑 상태면, 짙은 초록 강조색을 사용하는 A 시안을 선택했다.
- 빠른 장면은 모바일에서 한 줄에 3개가 보이는 현재 크기를 유지한다.
- 공간 탭은 `전체`를 첫 번째에 두고 사용자가 만든 공간을 뒤에 배치한다.
- 장면과 공간은 사용자가 이름을 정해 추가·삭제할 수 있다. `전체`는 시스템 통합 보기라 삭제하지 않는다.

## 인터랙션 프로토타입 디버깅

- 증상: 공간 편집 창에서 `부엌`을 입력하고 추가 버튼을 눌러도 탭과 개수가 갱신되지 않았다.
- 원인: 제출 이벤트에만 추가 동작을 연결한 초기 구현이 미리보기의 버튼 조작에서 실행되지 않았다. 입력 요소 조회도 폼 컬렉션의 이름 속성에 의존하고 있었다.
- 해결: 폼 내부의 `input[name="name"]`을 명시적으로 조회하고, 추가 버튼의 클릭 이벤트와 Enter 제출 이벤트가 같은 추가 함수를 호출하도록 변경했다.
- 검증 완료: `부엌` 공간과 `영화 보기` 장면을 각각 추가하고 삭제했다. `전체 → 거실 → 침실 → 부엌` 순서, 공간 2→3개 및 장면 3→4개 갱신, 테스트 항목 삭제 후 원래 상태 복구를 확인했다.

## 기기 추가 흐름

- 우측 상단 `+` 버튼에서 `기기 종류 → 연결 방식 → 이름과 공간 → 등록 확인`의 4단계 흐름을 시작한다.
- 기기 종류는 에어컨·조명·TV·센서를 우선 제공하고, 연결 방식은 IR·Wi-Fi/LAN·GPIO·기타로 분리했다.
- 등록 시 사용자가 기기 이름과 실제 공간을 선택한다. `전체`는 통합 보기이므로 배치 대상에서 제외한다.
- 등록 완료 후 선택한 공간 탭을 활성화하고 새 기기 카드를 보여주며 연결 기기 개수를 증가시킨다.
- 브라우저 검증: `에어컨 → IR 리모컨 → 테스트 에어컨 → 침실`로 등록해 확인 화면의 네 값, 새 카드, 5→6개 갱신, 침실 탭 선택을 확인했다. 검증 후 테스트 데이터는 새로고침으로 제거했다.

## 에어컨 상세 제어 화면

- 에어컨 카드를 선택하면 홈 대신 에어컨 상세 화면을 열고 뒤로 버튼으로 홈에 돌아간다.
- 상세 화면에는 전원, 17~30°C 희망 온도, 자동·냉방·제습·송풍 모드, 자동·약풍·중풍·강풍 풍량을 제공한다.
- 실제 리모컨에 있는 풍향 움직임/고정, 경제운전, 쾌속냉방, 에어컨 LED 기능을 추가 토글로 제공한다.
- 상세 화면에서 바뀐 전원·온도·모드·풍량은 홈의 에어컨 카드 요약에도 반영한다.
- 브라우저 검증: 희망 온도 24→23°C, 제습, 중풍, 풍향 고정, 경제운전, 쾌속냉방, LED 끄기와 전원 끄기/켜기를 조작했다. 상세 요약과 선택 상태가 바뀌고, 홈으로 돌아왔을 때 카드가 `제습 · 23°C · 중풍`으로 동기화되는 것을 확인했다.

## 색상 테마

- 사용자가 직접 선택하는 라이트·다크 두 가지 테마를 추가한다.
- 라이트는 기존 따뜻한 A 디자인을 유지한다.
- 다크는 검정에 가까운 전체 배경, 짙은 패널, 초록과 옅은 파랑 활성 상태를 사용한다.
- 홈, 에어컨 상세 화면, 기기 추가와 장면·공간 편집 창이 동일한 테마 토큰을 사용한다.
- 브라우저 검증: 다크에서 홈·장면 편집 창·에어컨 상세 화면이 정상 동작했고, 라이트로 다시 전환되는 것을 확인했다. 앱 배경/글자 계산 색상은 다크 `rgb(8, 10, 9)`/`rgb(240, 244, 241)`, 라이트 `rgb(244, 242, 236)`/`rgb(32, 35, 41)`로 바뀌었다.

## 자동화·시간 예약

- 리모컨의 제한적인 예약 기능을 복제하지 않고 라즈베리파이에서 시간을 관리하는 자동화 화면을 추가한다.
- 자동화는 이름, 실행 시간, 반복 요일, 대상 기기, 켜기/끄기 동작을 가진다.
- 각 자동화는 즉시 활성화·비활성화하거나 삭제할 수 있고, 새 자동화를 추가할 수 있다.
- 초기 예시는 평일 18:30 `귀가 전 냉방`과 매일 00:30 `취침 자동 종료`로 구성한다.
- 브라우저 검증: 첫 자동화를 비활성화해 활성 개수가 2→1개로 바뀌는 것을 확인했다. 평일 07:15 `출근 전 종료`, 에어컨 끄기를 추가해 2개 활성·3개 전체가 되었고, 새 자동화 삭제와 기존 자동화 재활성화 후 초기 2개 활성·2개 전체 상태로 복구했다.

## 전체 기기 화면

- 하단 `기기` 탭에서 등록된 모든 기기를 한곳에 보여준다.
- `전체`를 첫 번째 필터로 두고 사용자 공간별로 기기 목록을 좁힐 수 있다.
- 에어컨 카드는 기존 상세 제어 화면으로 연결하고, 조명·TV 같은 단순 카드는 빠른 전원 토글을 홈 카드와 동기화한다.
- 기기 화면의 `+` 버튼은 기존 4단계 기기 추가 흐름을 재사용한다.
- 브라우저 검증: 전체 4개 중 거실 필터에서 3개만 보이고 침실 센서가 숨겨지는 것을 확인했다. 기기 화면에서 TV를 켜면 홈 카드도 `켜짐`으로 동기화되었고, 테스트 후 다시 `꺼짐`으로 복구했다. 기기 화면에서 에어컨 상세로 들어갔다가 뒤로 이동하면 홈이 아닌 기기 화면으로 복귀하며, 기기 추가 버튼이 기존 4단계 등록 창을 여는 것도 확인했다.

## 더보기·시스템 설정

- `더보기` 탭에 집 이름, 공간, 빠른 장면, 기기 관리 진입점을 모았다.
- 집 이름은 편집 창에서 변경할 수 있고 홈 제목과 설정 화면의 현재 이름에 동시에 반영한다.
- 공간과 빠른 장면 관리는 홈에서 사용하던 편집 창을 재사용하고, 기기 관리는 전체 기기 화면으로 이동한다.
- 라이트·다크 선택을 설정 화면에도 배치하되 상단 미리보기 선택과 하나의 테마 상태로 동기화한다.
- 라즈베리파이, Tailscale, 웹 API 8001 포트의 연결 상태와 다시 확인 동작을 표현한다. 현재 단계는 UI 프로토타입이므로 실제 상태 조회 API 연결은 후속 구현 대상이다.
- 디버깅: 홈 요약은 연결 기기를 5개로 표시했지만 실제 카드와 전체 기기 화면은 4개였다. 기준을 실제 등록 카드 수로 통일해 초기 표시를 4개로 수정했다.
- 브라우저 검증: 집 이름을 `테스트 홈`으로 변경한 뒤 `우리 집`으로 복구했다. 공간·장면 편집 창, 기기 관리 화면 이동, 연결 상태 재확인, 라이트·다크 양쪽 선택 상태 동기화를 확인했다. 휴대폰 하단 내비게이션과 PC 좌측 내비게이션에서 동일한 더보기 화면이 정상 배치되는 것도 확인했다.

## 빠른 장면 편집·실행

- 기존 장면 카드는 하나를 계속 선택하는 방식이었지만 장면의 실제 의미와 맞지 않았다. 장면을 즉시 실행하는 버튼으로 변경하고 `실행 중… → 완료 → N개 동작` 상태를 표시한다.
- 빠른 장면 편집 목록에 각 장면의 `설정` 진입점을 추가했다. 새 장면은 동작 없이 생성되며 카드에 `설정 필요`를 표시한다.
- 장면 설정에서 장면 이름과 기기별 `변경 안 함·켜기·끄기`를 지정한다. 에어컨을 켤 때는 운전 모드, 17~30°C 희망 온도, 풍량을 지정하고 조명은 밝기를 지정한다. 상태만 제공하는 센서는 실행 대상에서 제외한다.
- 기본 장면은 `집에서` 2개 동작, `외출` 3개 동작, `취침` 3개 동작으로 구성했다.
- 현재 구현은 UI 상태와 기기 카드의 목표 상태를 동기화하는 프로토타입이다. 실제 실행 단계에서는 FastAPI 장면 실행 API가 의미 기반 명령을 각 기기 드라이버에 전달하고, Step 4에서 에어컨 IR 송신과 연결해야 한다.
- 브라우저 검증: `외출`을 실행해 에어컨·스탠드 조명·TV가 모두 꺼지고 실행 상태가 원래 동작 개수로 복귀하는 것을 확인했다. `취침`의 에어컨 목표를 27°C·중풍으로 변경해 저장한 뒤 실행했을 때 홈 카드가 `냉방 · 27°C · 중풍`으로 바뀌었다. `테스트 장면` 추가·삭제와 `설정 필요` 상태도 확인했으며, 검증 후 새로고침으로 기본값을 복구했다.

## 2026-08-30 실제 API 연결

- 프로토타입을 `app/static/index.html`로 편입하고 FastAPI의 `/`에서 제공한다.
- 상단과 에어컨 상세 화면에서 Mock/실제 송신 여부를 항상 표시한다.
- 지원 모델은 API에서 조회하며 현재 `Carrier CS-A061GS` 하나를 선택할 수 있다.
- 미지원 모델은 브랜드·모델명·필수 제품 사진, 선택 리모컨 사진·PDF를 제출할 수 있다.
- 에어컨 상세 제어와 빠른 장면의 에어컨 동작은 실제 FastAPI 명령 응답이 성공한 뒤에만 완료 상태로 처리한다.
- 조명·TV·센서는 아직 API에 연결하지 않고 카드에 `예시`를 명시한다.
