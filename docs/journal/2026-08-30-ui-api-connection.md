# 2026-08-30 Room First UI와 실제 API 연결

## 목표

별도 디자인 미리보기였던 Room First UI를 포트 8001의 정식 웹 화면으로 옮기고,
Carrier CS-A061GS 에어컨만 실제 FastAPI 기기 등록·명령 흐름에 연결한다. 송신 회로가
없는 현재 단계에서는 Mock 기록까지만 수행한다.

## 구현

- FastAPI `/`가 반응형 스마트홈 HTML을 제공
- 기존 서비스 상태 JSON은 `/api/v1/system`으로 이동
- UI 시작 시 지원 프로필, 등록 기기와 IR 전송기 상태를 병렬 조회
- Carrier 에어컨 등록이 없으면 프로토타입의 거실 에어컨을 최초 한 번 등록
- 실제 API 등록 기기 수와 `Mock IR 연결 · 실제 송신 없음` 표시
- 전원·온도·모드·풍량을 `set_state` API에 연결
- 풍향·경제운전·쾌속냉방·LED를 `execute` API에 연결
- `집에서`, `외출`, `취침` 장면의 에어컨 동작을 API 완료 대기 방식으로 변경
- 기기 추가 3단계에서 API 지원 모델 선택 추가
- 미지원 모델 사진·매뉴얼 업로드 폼 추가
- 조명·TV·센서는 `예시` 카드로 명시하고 로컬 동작 유지

## 브라우저 검증

인앱 브라우저를 디자인 미리보기 주소에서 `http://127.0.0.1:8001/`로 전환해 다음을
확인했다.

1. 첫 로드에 `Mock IR 연결 · 실제 송신 없음`, `1개 연결` 표시
2. 에어컨 상세에서 24→25℃ 조작
3. Mock 전송 기록 0→1 증가, 명령 ID `cool_25_high`
4. 풍향 움직임을 눌러 버튼이 풍향 고정으로 변경
5. 기록 1→2 증가, 명령 ID `swing_toggle`
6. 외출 장면 실행 후 에어컨 카드가 꺼짐으로 변경
7. 기록 2→3 증가, 명령 ID `power_off`
8. 집에서 장면 실행으로 냉방 24℃·강풍 복구
9. 기록 3→4 증가, 명령 ID `cool_24_high`
10. 기기 추가 화면에서 `Carrier · CS-A061GS` 모델과 미지원 모델 요청 버튼 확인
11. 브라우저 콘솔 warning/error 0건

최종 등록 기기 추정 상태는 냉방 24℃·강풍이며 실제 에어컨 상태를 확인한 값이 아니다.

## 디버깅

- 처음 브라우저 자동 검증에서 온도 올림 버튼을 `희망 온도 올리기`로 찾았으나 실제
  접근성 이름은 `온도 높이기`였다. DOM 상태를 다시 읽어 정확한 이름으로 검증했다.
- 기기 추가 창의 `에어컨` 버튼은 홈 카드와 이름이 겹쳐 strict selector가 2개를
  찾았다. 정확히 일치하는 버튼을 선택해 모델 단계까지 검증했다.

## 남은 범위

- Raspberry Pi에는 이번 UI와 API 변경을 아직 배포하지 않았다.
- 실제 IR 출력은 Step 4의 Local GPIO 전송기 이후 가능하다.
- 장면·공간·자동화의 서버 영구 저장은 후속 단계다.
- 조명·TV·센서용 프로필과 전송 어댑터는 아직 없다.
