# 2026-10-02 — 설치별 가족 FCM 구현·배포·실제 등록과 수신

## 승인과 작업 범위

사용자가 FCM 후속 작업 진행, Google Cloud 기본 약관 동의, 전송 전용 서비스 계정 `a50-fcm-sender`, FCM API Admin 역할, 서버 JSON 키 연결을 승인했다. 유료 결제·무료 체험은 요청하지 않았고 신청하지 않았다. 최초 Cloud 약관 화면에서 제품화 개발의 현재·향후 상업적 사용 계획 항목을 선택했다. 이메일 업데이트는 선택하지 않았다.

## 구현

중앙 서버 0.3.0, DB 스키마 3. 설치 증명 해시·계정·FCM 토큰·등록 버전, 이벤트 저장과 같은 트랜잭션의 영구 대기열, 발송 직전 가족/설치 재확인, 5분 만료·6회 제한 재시도·임대 복구, UNREGISTERED 토큰 비활성화에 등록 버전 비교를 추가했다. 전송 키가 없으면 시험 요청은 503이다. Google Auth Library 기반 HTTP v1만 사용한다. FCM 데이터에는 집 이름·센서 값을 넣지 않는다.

Android 0.2.0/versionCode 2는 Google 프로젝트 발신자 ID·Messaging·WorkManager, 알림 채널·Android 13 권한 UI, 설치 등록·토큰 갱신, 로그아웃/서버 변경 시 즉시 로컬 차단, 계정/등록 버전·메시지 중복 수신 검사를 포함한다. 알림 켜기·끄기와 소유자의 해당 단말 시험 알림 버튼을 추가했다. 앱은 기존 전용 인증서로 서명했다.

## 실제 검증

- 최종 로컬 관련 검사 76개 통과(5.40초), 새 Python 파일 8개의 Ruff 검사 통과. Android 단위 검사 4개, 실패·오류 0개. 실제 FCM send를 흉내 낸 공급자 시험은 수신 증거가 아니다.
- A50 기존 배포 체크섬 미리보기 통과 후 `v0.3.0-6b885a7b50e31dcc`의 19개 파일 배포. 기존 SQLite 일관 백업, 2→3 추가 마이그레이션, 초기 런타임 식별값·SSH 부팅 파일·사용자/집 보존. 무결성 ok, live/ready 정상.
- 최종 Python 포맷 정리 후 미리보기와 명시적 재배포를 수행했다. 현재 배포는 `v0.3.0-f8fb6d28131c91a0`이다. 기존 파일 변경 충돌 없음, 일관 DB 백업·ready 정상·19개 코드/훅 SHA256 일치를 확인했다. 241은 최종 검사, 242는 미리보기, 243은 반영 기록이다.
- 전송 의존성은 Termux Python 3.14에 설치했다. charset-normalizer의 공식 Android arm64 wheel을 사용했고 새 native 빌드를 요구하지 않았다. pip check 통과.
- 중앙 서비스만 재시작. 터널 PID와 주소 유지, 외부 HTTPS의 시스템 인증서 검증·ready 200·무인증/위조 인증 401 통과.
- 앱 release 4,389,669 bytes, SHA256 `834f3354c5c9e163945d94a178b6f0bc4faf2128e326b13db7a10b7b8a18dd1d`. 서명·실제 Google 구성·FCM 발신자·수신 서비스·release HTTPS·시험 계정 제외 검사 통과.
- `install -r`로 A50에 데이터 삭제 없이 업데이트하고 설치된 APK 해시가 로컬 release와 일치함을 확인했다.
- 실제 Google 세션으로 알림 설정 UI의 설치 등록 시험 1개를 5.361초에 통과했다. 실제 FCM 등록 토큰과 설치 등록 버전이 서버에 연결됐으며 토큰은 내보내지 않았다. 클라이언트 재실행 후 로그인·HTTPS 주소·기존 집 확인.
- 키 연결 전 읽기 전용 DB 검사: 사용자 1, 집 2, 허브 0, 이벤트 0, 설치 1, 전송 작업 0. 활성 설치 1개의 토큰 존재를 확인했다. 이 시점에는 서버 키 설정이 없었다.
- 바탕화면에 `가족스마트홈-0.2.0.apk` 전달. 이전 0.1.0 파일을 보존했다.
- 최종 배포 후 244~245에서 기존 DB·SSH 부팅·소스 일치·외부 HTTPS를 다시 확인했다. 터널 PID를 유지했다. 247에서 실제 `Display Power: state=OFF`와 화면 꺼진 상태의 SSH·중앙 API ready를 확인했다. 이 결과는 FCM 화면 꺼짐 수신 시험이 아니다.

## 실패와 해결 과정

초기 pytest 호출에 잘못된 시험 파일명을 사용해 exit 4였다. 실제 파일 목록 확인 후 고쳐 최종 관련 시험을 통과했다. 브라우저 화면 캡처 1회는 CDP 요청 제한 시간 오류였고 새 화면 관찰 후 Google Cloud 화면 캡처를 저장했다.

마지막 화면 정리 검사에서는 일반 Android의 `mWakefulness=Asleep` 문자열을 기대했지만 Samsung 출력에 해당 필드가 없어 검사가 중단됐다(246). 실제 출력의 `Display Power: state=OFF`를 기준으로 읽기 전용 검사를 고쳐 통과했다(247). 화면 끄기 자체의 실패로 해석하지 않는다.

Google Cloud에서 FCM HTTP v1이 이미 활성화된 것을 확인했다. 전용 서비스 계정 생성과 FCM 역할 부여, JSON 키 1개 생성이 완료됐고 콘솔에 ‘비공개 키가 컴퓨터에 저장됨’이 표시됐다. 그러나 생성 전에 다운로드 이벤트 수집을 연결하지 않아 파일 경로를 얻지 못했다. 뒤늦은 이벤트 대기는 타임아웃이다. 사용자 폴더에서 알려진 정확한 파일명으로 검색했지만 파일을 찾지 못했다. 첫 검색의 Windows 기본 cp949 디코딩 오류도 UTF-8을 명시해 수정했으며 검색 결과는 0이었다. 저장 경로가 다른 드라이브일 가능성 등은 확인되지 않은 추정이다.

이미 생성한 키를 중복 생성하지 않았다. 사용자에게 노트북 Chrome 다운로드 목록의 파일 저장 위치만 요청했다. 키 내용·비밀번호를 채팅으로 요청하지 않았다. 최초 바탕화면 점검에는 앱 구성 JSON 두 개만 있어 서버 키와 구분해 안내했다. 이후 사용자가 다시 다운로드했다고 알려줘 전용 서비스 계정 JSON을 확인했다. `configure_a50_fcm.py` 미리보기(248)·반영(249)에서 프로젝트·계정·RSA 키 검증, 비공개 stdin 전송, 0600 파일·설정 백업·중앙 서버만 재시작·ready를 통과했다.

첫 실제 백그라운드 시험은 `Own-family button did not accept click`으로 실패했다(251). 집 이벤트 조회 중 비활성 버튼을 기다리지 않은 검사 helper의 문제였다. 읽기 전용 점검은 전송 작업 0개를 확인했다(253). 첫 읽기 전용 SQL 점검도 Python 문자열의 중첩 따옴표 때문에 SyntaxError였다(252). 파라미터 바인딩으로 수정한 253 점검이 통과했고 데이터 변경은 없었다.

검사 helper가 버튼 활성화를 기다리도록 수정해 시험 APK만 재빌드했다(254). 실제 release APK는 기존 해시를 보존했다. 실제 UI의 전송 요청 → 홈 화면 → 실제 수신 콜백 시각 → 자기 앱의 실제 시험 알림 게시를 모두 검사해 8.669초에 `OK (1 test)`였다(255). Google 전송 작업 `accepted` 1개를 확인했고, 이를 콜백·게시 검사의 보조 증거로만 사용했다(256).

첫 수신 후 스크린샷은 접근성 문구와 실제 렌더링 프레임 시점이 달라 집 목록을 보여줬다. 캡처 전에 main UI idle·350ms 프레임 대기·문구 재확인을 추가했다. 실제 수신 검사 APK에 화면 꺼짐 조건을 추가하고 재빌드했다(257). 화면을 끄고 `PowerManager.isInteractive() == false`를 확인한 뒤, 같은 Firebase SDK·원래 인증 API로 해당 소유자의 지정한 집과 자기 설치만 시험 전송했다. 토큰은 휴대폰 밖으로 내보내지 않았다. 새 콜백·알림 게시·수신까지 비활성 화면을 확인해 8.227초에 통과했다(258). 이후 화면을 켜 실제 ‘최근 알림 수신 완료’ UI를 캡처했다.

집·서버·터널 읽기 전용 점검도 통과했다(259~260). 프레임 대기 수정 후 백그라운드 수신·수신 UI 캡처를 다시 검사해 8.771초에 통과했다(261). 기존 세션·주소·집 목록을 매번 클라이언트 재실행 후 확인했다.

최종 읽기 전용 상태(262): 개인 키 0600, DB 무결성 ok, 접수 작업 3개, 사용자 1·집 2·허브 0·센서 이벤트 0·설치 1. USB 충전 중, 배터리 100%, 보고 온도값 300(섭씨 30.0도). 실제 시험은 같은 Wi-Fi와 기존 Termux 서버 운영 조건이다. 수신 앱과 중앙 서버를 같은 A50에서 시험했다.

작업 후 홈 화면으로 돌아가 표시를 끄고 실제 `Display Power: state=OFF`를 확인했다(263). 화면 꺼진 상태에서도 관리 SSH와 중앙 API ready가 정상이고 전송 키 설정이 파일에 유지됨을 확인했다. Python 관리 스크립트 구문 검사와 바탕화면 APK의 검증된 release 해시 일치도 통과했다.

## 남은 검증

다른 가족 단말·다른 집 실계정의 실제 수신 격리·장시간·깊은 절전·네트워크 변경·새 FCM 설정 적용 후 재부팅·실제 Pi 센서 송신은 미검증이다. 즉시 화면 꺼짐 수신을 장시간 절전 보장으로 해석하지 않는다.
