# 0015 — 가족 권한과 앱 설치 등록으로 FCM 수신자를 결정한다

날짜: 2026-10-02. 상태: 코드·로컬 시험·A50 앱 설치 등록 검증 완료. 실제 전송 검증은 서버 키 연결 후 별도로 기록한다.

## 선택

Pi 이벤트의 집은 등록된 허브 자격으로만 결정한다. 이벤트 저장과 알림 전송 대기열 생성은 같은 SQLite 트랜잭션에서 처리한다. 주제(topic) 구독으로 가족 권한을 대체하지 않는다.

각 앱 설치는 임의 UUID와 256비트 설치 증명, 로그인 계정, FCM 등록 토큰을 연결한다. 설치 증명은 서버에 해시로 저장하며 앱 데이터 백업은 허용하지 않는다. 토큰은 서버 전송에 필요하므로 원문을 비공개 DB에 저장한다. 등록·회전·계정 변경은 인증된 API를 사용하고, 다른 설치의 동일 토큰 재등록은 충돌로 거부한다. 한 계정의 활성 설치는 최대 10개다.

전송 직전에 활성 사용자·현재 가족 참여·설치 소유 계정·등록 버전을 확인한다. 늦게 도착한 등록 해제나 FCM `UNREGISTERED` 응답이 새 토큰을 끄지 않도록 등록 버전도 비교한다. 이벤트 재전송은 기존 이벤트 ID/내용 비교로 중복 대기열 생성을 방지한다.

FCM에는 집 이름·센서 값·상세 기록을 보내지 않는다. 데이터 메시지에는 메시지 ID·수신 계정 식별값·설치 등록 버전·종류만 담는다. 앱은 현재 로그인 계정, 알림 활성 상태, 등록 버전을 확인한 뒤 일반 알림을 게시한다. 기록은 앱의 인증된 API 요청으로 조회한다. 로그아웃·연결 서버 변경은 즉시 로컬 수신을 끄고 기존 알림을 닫는다. 네트워크가 가능하면 서버 등록도 해제한다.

서버 전송은 Google Auth Library와 FCM HTTP v1을 사용한다. 사용자 Firebase 로그인 토큰과 서버 서비스 계정 키의 역할을 분리한다. 전송 전용 계정에는 `Firebase Cloud Messaging API Admin` 역할을 부여하고 키는 소스·APK·로그에 넣지 않는다. 장비의 비공개 설정에 별도로 설치한다.

## 운영 한계

- SQLite 대기열은 재시작 후 남고, 전송 중 작업은 60초 임대가 끝나면 다시 확인한다. 일시적 실패는 최대 6회, 메시지는 5분 후 만료한다. `Retry-After`는 최대 300초다.
- FCM HTTP 200은 Google 접수 완료다. 실제 단말 콜백·알림 게시 성공은 별도로 검사한다.
- Google 접수 직후 서버가 종료되면 재시도로 중복 전달될 수 있다. 앱은 최근 메시지 ID 최대 100개를 기억한다. 무제한·영구적인 exactly-once 보장은 아니다.
- 권한 확인과 Google 전송 사이에는 외부 I/O가 있어 완전한 원자성이 없다. 이미 Google에 넘긴 메시지를 회수하지 못한다. 상세 기록을 넣지 않는 이유다. 가족 권한 회수 뒤 앱의 기록 API는 즉시 차단한다.
- 오프라인 로그아웃은 로컬 수신 차단이 즉시 적용되지만 서버 등록 해제 성공을 보장하지 못한다. 이후 같은 설치의 재등록은 등록 버전을 바꾼다. 90일 갱신 없는 토큰은 선택·정리에서 제외한다.
- 전송 진단은 14일 보존 후 정리한다. 사용자·집·기존 센서 기록을 자동 삭제하지 않는다.
- 일시적 HTTPS 주소, Android 전원 관리, 서버 네트워크·Google Play 서비스 상태 때문에 도착이 지연되거나 누락될 수 있다. 안전 경보의 유일한 전달 경로로 쓰기 전 별도 설계가 필요하다.
