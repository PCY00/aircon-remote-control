# ADR-0003: IR 학습·제어 계층과 UI를 분리한다

## 상태

채택

## 배경

기존 리모컨 신호의 반송파, 프레임 구조와 체크섬이 아직 측정되지 않았다. 에어컨 리모컨은 전체 상태를 긴 프레임으로 보낼 가능성이 있고, 단방향 IR이므로 실제 에어컨 상태를 API가 확정할 수도 없다. 이 상황에서 UI부터 구현하면 검증되지 않은 기능과 잘못된 상태 표현이 고정될 수 있다.

## 결정

프로젝트를 다음 세 단계로 분리한다.

1. 실행·원격접속 환경 구성
2. IR 학습·송신과 하드웨어 API
3. 최종 사용자 UI

Step 2에서는 수신 학습 경로와 송신 제어 경로를 분리한다. 초기 구현은 검증된 원시 IR 프리셋 재생을 허용하고, 프로토콜 디코더는 측정 결과가 충분할 때 추가한다. API 라우터는 GPIO나 `ir-ctl`을 직접 실행하지 않고 IR backend 인터페이스를 호출한다.

API 상태는 에어컨의 실제 확정 상태가 아니라 `last_commanded`임을 명시한다. UI는 Step 2에서 확정된 capabilities와 상태 의미만 사용한다.

## 결과

- 하드웨어 없이도 mock backend로 API를 테스트할 수 있다.
- 원시 신호 재생 성공 후 프로토콜 분석을 점진적으로 진행할 수 있다.
- UI가 검증되지 않은 온도·모드 조합을 노출하지 않는다.
- 기존 리모컨 사용에 따른 상태 불일치를 제품 설계에서 숨기지 않는다.
- 수신기와 송신기 문제를 독립적으로 진단할 수 있다.
