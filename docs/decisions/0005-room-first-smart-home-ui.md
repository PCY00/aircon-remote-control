# ADR-0005 — Room First 스마트홈 UI

## 결정

Step 3 UI는 특정 에어컨 리모컨 앱이 아니라 여러 공간과 가전제품을 수용하는
스마트홈 플랫폼으로 설계한다. 디자인 방향은 `A · Room First`로 확정한다.

## 정보 구조

```text
집 → 공간 → 기기 → 기기가 제공하는 기능
```

- 홈은 공간, 즐겨찾는 기기, 장면과 요약 상태를 보여준다.
- 홈의 핵심 정보 순서는 빠른 장면을 먼저, 공간과 기기 목록을 다음에 배치한다.
- 빠른 장면은 현재의 큰 카드 표현을 유지하며 사용자가 장면을 추가하거나 삭제할 수 있다.
- 공간 탭은 `전체`를 항상 첫 번째에 두고 그 뒤에 사용자가 만든 공간을 배치한다.
- `거실`, `침실` 같은 공간 이름은 고정값이 아니다. 원룸·대형 주택 등 실제 주거 형태에 맞춰 사용자가 원하는 이름으로 공간을 추가하고 삭제할 수 있어야 한다.
- `전체`는 시스템이 제공하는 통합 보기이므로 이름 변경이나 삭제 대상에서 제외한다.
- 기기 추가는 `기기 종류 → 연결 방식 → 이름과 공간 → 등록 확인` 순서의 단계형 흐름을 사용한다.
- 기기 종류와 연결 방식은 분리한다. 같은 에어컨도 IR·Wi-Fi 등 서로 다른 드라이버를 사용할 수 있고, 새 연결 방식을 추가해도 사용자용 기기 구조는 유지한다.
- 기기를 등록할 때 사용자가 이름과 배치할 공간을 선택하며, 등록 완료 후 해당 공간의 기기 목록에 바로 표시한다.
- 에어컨 상세 화면은 기기별 기능(capability)을 조합한다. 현재 에어컨에는 전원, 희망 온도, 운전 모드, 풍량, 풍향, 경제운전, 쾌속냉방, 본체 LED 기능을 노출한다.
- 에어컨 카드 선택은 카드에서 전원을 바로 토글하지 않고 상세 제어 화면으로 이동한다. 다른 단순 기기는 카드에서 빠른 토글을 유지할 수 있다.
- 색상 테마는 우선 사용자가 직접 선택하는 `라이트`와 `다크` 두 가지를 제공한다. 라이트는 따뜻한 A 팔레트를 유지하고, 다크는 검정에 가까운 배경에 동일한 초록·옅은 파랑 강조 체계를 사용한다.
- 리모컨 자체의 예약 패킷 대신 라즈베리파이의 자동화 스케줄러가 시간 예약을 담당한다.
- 자동화는 이름, 실행 시간, 반복 요일, 대상 기기, 수행 동작을 저장하며 사용자가 활성화·비활성화하거나 삭제할 수 있다.
- `기기` 탭은 모든 등록 기기를 한곳에서 보여주고 `전체` 및 사용자 공간으로 필터링한다. 에어컨은 상세 제어로 이동하고 단순 기기는 카드에서 빠르게 토글한다.
- 기기 화면은 에어컨·조명·TV·센서 등 서로 다른 기능 집합을 지원한다.
- `더보기` 탭은 일상 제어 화면과 관리 기능을 분리한다. 집 이름, 공간, 빠른 장면, 기기 목록을 한곳에서 관리하고 테마와 라즈베리파이·Tailscale·웹 API 연결 상태를 확인한다.
- IR 리모컨 프로필은 사용자용 최상위 메뉴가 아니라 기기 연결 드라이버에 속한다.
- 새 리모컨과 새 통신 방식은 같은 기기 모델 아래에 추가할 수 있어야 한다.
- 장면은 여러 기기를 한 번에 원하는 상태로 바꾸고, 자동화는 조건과 시간을 담당한다.
- 장면에는 IR 원시 파형이 아니라 `기기 ID + 의미 있는 목표 상태`를 저장한다. 실행 시 각 기기 드라이버가 목표 상태를 IR·Wi-Fi·GPIO 명령으로 변환한다.
- 장면 카드는 지속적으로 선택되는 모드가 아니라 즉시 실행 버튼이다. 실행 중과 완료 상태만 잠시 표시하고 다시 저장된 동작 개수로 돌아간다.

## 반응형 원칙

- 휴대폰에서는 앱처럼 보이는 단일 열과 하단 내비게이션을 사용한다.
- PC에서는 같은 웹앱이 좌측 사이드바와 넓은 기기 그리드로 재배치된다.
- PC 레이아웃은 최대 1920×1080을 기준으로 하고 더 작은 화면에서는 뷰포트 안으로 줄인다.
- 기본값은 화면 폭을 감지하는 `자동`이며, 사용자는 `더보기 → 화면 구성`에서 휴대폰 또는
  PC 레이아웃을 강제로 선택할 수 있다. 선택은 브라우저별 로컬 저장소에 보존한다.
- Raspberry Pi에 직결할 13인치 터치 화면에서는 벽면 대시보드 모드를 사용한다. 센서
  요약과 빠른 장면을 항상 보이고 에어컨 제어를 큰 터치 영역으로 제공한다.
- 터치 대시보드는 마우스 hover나 키보드 입력에 의존하지 않으며 주요 조작 영역은 최소
  48 CSS px를 목표로 한다.
- 별도의 모바일 사이트를 만들지 않고 하나의 반응형 코드베이스를 사용한다.
- 핵심 기능은 320px 폭에서도 가로 스크롤 없이 사용할 수 있어야 한다.
- 디자인 검토용 배지와 화면·테마 도구 모음은 운영 홈에 노출하지 않고 `더보기` 설정으로
  통합한다.

## 시각 방향

- `A · Room First`의 따뜻한 아이보리·연한 블루·짙은 그린 색감을 사용한다.
- 기술 장비 화면보다 생활 공간에 어울리는 편안한 인상을 우선한다.

## 선택 이유

Room First 구조는 사용자가 통신 방식보다 실제 생활 공간과 기기를 먼저 찾게 한다.
현재 Carrier 에어컨뿐 아니라 향후 조명·TV·센서·플러그 같은 장치를 추가해도
내비게이션 구조를 바꾸지 않아도 된다.
