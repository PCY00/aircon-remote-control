# 0013 — Firebase Google 인증과 중앙 서버의 집별 권한

2026-10-02, 사용자 선택으로 Google/Firebase Authentication 채택.

Firebase는 사용자 인증을 담당하고 집·기기·가족의 권한은 A50 SQLite가 관리한다.
토큰에 들어 있는 임의 역할·클라이언트 집 ID는 권한으로 사용하지 않는다.
Firebase issuer/subject로 계정을 식별하며 검증한 Google 이메일로 초대 수신자를 확인한다.
현재 활성 회원을 매 요청 확인해 집 권한 회수가 유효 로그인 토큰보다 우선한다.

소유자 고정, 가족(member), 조회(viewer)의 세 역할. 명령 API는 다음 단계라 member/viewer는
현재 같은 조회 범위다. 가족 전체 주소록과 초대·등록·해제는 소유자만 관리한다.
초대 24시간/한 번, 기기 claim 10분/한 번, 둘 다 원문 대신 해시 저장.
제외 이전 초대는 감사 기록 순서로 차단한다. 계정 재생성의 동일 이메일은 자동 승계하지 않는다.

한 집 한 활성 허브. 관리자 SSH에서만 기기 키를 발급하며 HTTP 발급 기능은 제공하지 않는다.
키의 등록된 집을 서버가 이벤트에 부여한다. 기기 해제 후 전송 거부, 과거 이벤트 유지.
클라이언트가 event_id를 재전송하면 동일 내용만 중복 처리한다.

Google HTTPS X509 공개키/캐시 만료 준수, RS256·프로젝트·발급자·시간·고유 사용자·
Google provider·확인된 이메일 검증. Firebase Admin의 전역 계정 폐기 조회는 아직 하지 않는다.
인증 정보는 실제 비공개 설정으로 관리하며 미설정/공개키 조회 장애는 닫힌 응답을 반환한다.
서비스 계정 키·FCM 발송 권한은 이번 작업에 생성하지 않았다.

Termux prebuilt cryptography 50.0.2를 system-site-packages 가상환경에서 사용해 Rust 빌드를 피했다.
공유 가상환경·시스템 패키지 의존성이 있으므로 다음 업데이트도 pip check와 장비 검증을 수행한다.
SQLite backup API로 정상 중지 상태의 일관 백업 후 트랜잭션으로 스키마를 확장한다.
백업은 자동으로 운영 DB에 덮어쓰지 않으며 이후 새 데이터가 있으면 복구 전 차이를 검토한다.

Firebase 콘솔은 Spark 무료, Google 로그인 제공자와 가족 Android 앱·서명 지문 등록 완료.
실제 구성의 가족 APK 빌드·서명·시험 계정 제외·A50 설치와 시작 확인 완료.
사용자 로그인·외부 네트워크 통로·FCM·실제 기기 연결은
후속 검증으로 분리한다. 127.0.0.1:8001 바인딩 유지.

가족 앱은 production/fixture 빌드를 분리한다. production에는 서명한 가상 계정 토큰을
포함하지 않는다. fixture는 별도 패키지와 눈에 보이는 시험 표시를 사용하고 임시 DB·루프백
8765 포트에만 연결한다. 배포 APK는 HTTPS와 시스템 인증서를 사용하며 토큰을 다른 주소로
전달하는 리디렉션을 따라가지 않는다. 주소 변경 시 기존 계정을 로그아웃해 새 서버에
기존 토큰이 자동 전달되지 않게 한다. 첫 주소 설정은 로그인 상태를 유지한다.
