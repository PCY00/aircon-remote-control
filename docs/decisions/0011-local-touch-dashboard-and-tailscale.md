# ADR-0011 — 13인치 로컬 터치 대시보드와 Tailscale 원격 접근

- 상태: 소프트웨어 구성 완료, 실물 화면 검증 대기
- 날짜: 2026-09-07

## 배경

Raspberry Pi에 13인치 터치 디스플레이를 직접 연결해 집 안에서는 항상 켜진 스마트홈
패널로 사용하고, 집 밖에서는 기존 웹앱에 Tailscale로 접속한다. 현재 Raspberry Pi OS는
64비트 Lite이므로 디스플레이를 연결하는 것만으로 브라우저 UI가 실행되지는 않는다.

## 결정

- 모바일·PC·벽면 패널 모두 같은 FastAPI 웹앱과 의미 기반 기기 API를 사용한다.
- 13인치 화면은 별도 제품이 아니라 반응형 웹앱의 `wall/kiosk` 레이아웃으로 제공한다.
- 벽면 홈 화면에는 현재 온도·습도, 문 열림 상태, 센서 배터리, 마지막 갱신 시간,
  에어컨 상태와 빠른 장면을 우선 표시한다.
- 센서 상태는 브라우저가 MQTT에 직접 연결하지 않고 FastAPI의 정규화된 상태 API와
  SSE 또는 WebSocket을 통해 받는다.
- 내부 Zigbee 이름, 사용자 표시 이름과 공간 이름을 분리한다. 예를 들어
  `sensor_door_01`은 안정적인 내부 ID이고 UI에는 `현관문`처럼 사용자가 정한 이름을 쓴다.
- 터치 조작은 hover와 키보드 없이 가능해야 하며 주요 버튼은 최소 48 CSS px, 충분한
  간격, 명확한 누름·처리·성공·실패 피드백을 제공한다.
- `online`, `offline`, `stale`을 구분하고 마지막 수신 시각을 표시해 오래된 센서 값을
  현재값처럼 보이지 않게 한다.
- 도어센서는 현재 열림·닫힘뿐 아니라 실제 상태가 바뀐 시각과 최근 전환 이력을 보존한다.
  같은 상태의 반복 보고와 retained 메시지는 새 이벤트로 만들지 않는다.
- 온습도는 `07:00–19:00`을 기본 수동 전용 시간으로 두어 이 시간에는 자동 갱신하지
  않는다. 사용자가 수동 전용 시작·종료 시각, 자동 갱신 활성화 여부와 간격을 바꿀 수
  있고 수동 갱신은 항상 제공한다.
- 배터리식 Sleepy End Device는 서버 요청만으로 즉시 깨어난다고 가정하지 않는다. 수동
  갱신은 새 측정 성공, 다음 보고 대기와 최신 저장값 재조회를 화면에서 구분한다.
- 집 밖에서는 계속 Tailscale 사설망만 사용하며 공용 포트포워딩은 하지 않는다.
- 집 안의 직결 패널은 인터넷이나 외부 클라우드 장애와 무관하게 로컬에서 동작해야 한다.

## 로컬 실행 계획

1. 디스플레이의 해상도, 회전 방향, 터치 입력 장치와 화면 꺼짐 동작을 실물로 확인한다.
2. Pi OS Lite에 필요한 최소 Wayland/그래픽 세션과 Chromium만 설치한다.
3. 부팅 후 전용 사용자 세션에서 Chromium을 전체 화면 키오스크로 자동 실행한다.
4. 웹앱과 브라우저가 늦게 시작되거나 종료돼도 자동 복구되도록 별도 systemd 서비스를
   둔다.
5. 화면 전용 상태표시, 네트워크 단절, Zigbee/MQTT 단절과 8001 앱 재시작을 실기 검증한다.

현재 8001 서비스는 Pi의 Tailscale IPv4 한 개에만 바인딩돼 있다. 로컬 패널도 Pi 자신의
Tailscale 주소를 열도록 구현해 별도 공개 리스너나 `0.0.0.0:8001` 노출을 추가하지 않았다.
키오스크 런처는 디스플레이, Tailscale 주소와 `/health`를 순서대로 기다린 뒤 브라우저를
시작한다.

## 대시보드 우선 정보 구조

```text
집 상태 요약
├─ 온도 / 습도 / 갱신 시각
├─ 문 열림 / 닫힘 / 마지막 변경 시각 / 최근 이력 / 센서 배터리
├─ 에어컨 현재 설정과 빠른 제어
├─ 빠른 장면
└─ 연결 상태: API / MQTT / Zigbee
```

기기 상세 설정, 공간·아이콘 편집과 새 모델 요청 같은 관리 기능은 기존 `더보기`와 기기
상세 화면에 유지해 벽면 홈 화면을 복잡하게 만들지 않는다.

기기 추가에는 `Zigbee 센서 추가` 마법사를 제공한다. 제한 시간 페어링, 모델 발견,
지원 여부 확인, 이름·공간·아이콘 지정과 자동 가입 종료를 한 흐름에서 처리한다.

## 결과

- 집 안에서는 전용 터치 패널, 외부에서는 휴대폰·PC로 같은 상태와 제어 기능을 사용한다.
- 화면 크기별로 별도 앱을 유지하지 않아 상태 모델과 제어 로직이 갈라지지 않는다.
- Pi OS Lite의 가벼운 운영 기반은 유지하면서 필요한 GUI 구성만 추가할 수 있다.
- Cage, Chromium과 한글 글꼴을 Pi에 설치했고 `aircon-kiosk.service`를 활성화했다.
- 디스플레이 미연결 상태에서는 서비스가 재시작 루프 없이 연결을 기다린다.
- 실제 화면, 터치, 회전과 절전 동작 검증은 디스플레이 연결 후 완료한다.
