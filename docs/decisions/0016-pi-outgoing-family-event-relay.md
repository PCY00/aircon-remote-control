# 0016 — Pi의 기존 기록을 독립 서비스로 가족 중앙 서버에 전달

날짜: 2026-10-02. 상태: 구현·미리보기 완료, 첫 허브 인증키·운영 연결 승인 대기.

기존 Pi 앱의 문 센서·자동화 경고 DB를 읽는 독립 서비스를 둔다. 센서 DB, MQTT 처리, 에어컨
제어 API는 현재 운영 버전을 보존한다. Pi 원격 파일 여섯 개와 로컬의 차이는 2026-09-12에
문서화한 미배포 개선과 일치한다. 이 연결 작업에 기존 앱 배포를 함께 넣지 않는다.

Pi마다 개별 허브 키를 발급한다. 사용자의 실제 Google 소유자 권한과 10분 유효 일회용 등록 코드를
통과해야 집에 연결된다. 중앙 서버는 전송자의 본문에서 집 ID를 받아 믿는 대신 허브에 연결된 집을
조회한다. FCM 대상은 그 집의 현재 활성 가족·설치로 결정하고 전송 직전에 권한을 다시 검사한다.
전용 FCM 서비스 계정 키는 A50에만 둔다. Pi에는 개별 허브 키만 둔다.

별도 SQLite 대기열에서 진행 위치·재시도 본문·ID를 보존한다. 첫 시작의 기존 기록은 건너뛴다.
통신 응답을 잃어 재전송해도 중앙 서버는 같은 허브·기록 ID를 중복 저장하거나 알림 작업을 추가하지 않는다.
문 변화와 경고 발생·해제만 전달하며 MAC, 장치 원본 식별자, 방 이름, 원시 MQTT·자동화 snapshot은 제외한다.

센서 발생 후 240초 안에서 알림을 전송한다. 중앙 서버 0.3.1은 선택 항목
`notification_expires_at`을 검증하고 유지한다. 무기한·미래 300초 초과·비수치 값은 거절하고,
이미 만료된 도착 기록은 새 FCM 작업으로 만들지 않는다. 기존 형식은 중앙 수신 시점의 300초 기본값을 유지한다.
스키마 3과 기존 등록 정보를 유지한다.

서비스·로그·대기열에 제한을 둔다. DB 교체·번호 초기화·인증 거절 때 자동으로 재등록하거나
과거 기록을 다시 읽지 않고 조사하도록 중단한다. 시험은 실제 `hub.connection_test`를 사용해
센서 동작으로 오인하지 않게 구분한다. 실제 문 변화 검증은 물리 이벤트가 생긴 뒤 기록한다.

Pi의 기존 Tailscale 에어컨 API 경로를 유지한다. 새 연결은 승인된 중앙 HTTPS에 나가는 요청만 사용한다.
고정 도메인·터널 주소 갱신·가족 추가 단말·장시간 운용은 이후 과제다.
