# 결정 0004: 예약 실행은 Raspberry Pi가 담당한다

## 상태

채택

## 배경

실물 리모컨은 TIMER ON/OFF 지연시간을 0.0–24h 범위로 편집하고, 약 1초 동안 입력이 없으면 예약 커밋 패킷을 전송한다. TIMER ON 1.5h 패킷 한 건을 확보해 리모컨 자체 예약 프로토콜이 존재함을 확인했다.

그러나 웹 원격 제어의 목적은 Tailscale을 통해 예약을 생성·조회·취소하고, 실행 결과를 기록하는 것이다. 본체 내장 타이머 패킷을 사용하면 Raspberry Pi가 본체 내부 예약 상태를 다시 읽을 수 없고 프로토콜 전체 해독도 추가로 필요하다.

## 결정

- 예약 시간과 대상 상태는 Raspberry Pi에 영속 저장한다.
- 예약 시각이 되면 Pi가 이미 검증한 명시적 운전 상태 또는 OFF IR 패킷을 전송한다.
- TIMER ON/OFF 원시 패킷은 연구·블로그 자료로 보존하지만 제품 예약 기능에는 사용하지 않는다.
- 추가 TIMER 시간·종류 필드 해독은 필수 개발 범위에서 제외한다.

## 결과

- 웹 UI에서 예약 목록과 남은 시간, 취소 여부를 정확히 표시할 수 있다.
- 서비스 재시작 후 예약 복구와 실행 로그를 제공할 수 있다.
- 본체 내부 예약 상태를 조회할 수 없는 문제를 피한다.
- 시스템 시간이 정확해야 하므로 시간 동기화 상태를 운영 점검에 포함한다.
