# [편하게 살자] 스마트홈 알림 - 같은 앱을 써도 자기 집만 보게 만들었다

　A50에서 서버가 응답하는 것까지 확인했다. 이제 로그인과 가족 권한을 붙여보기로 했다.

　처음 생각한 조건은 간단했다. 라즈베리파이 한 대에 가족 여러 명이 붙는 것은 괜찮다. 그런데 다른 집 사람이 앱을 설치했다고 우리 집 문 열림 알림까지 받으면 안 된다.

　Google 로그인을 넣는 것만으로 이 문제가 끝나지는 않는다. 누군지는 알아도 어느 집에 들어갈 수 있는지는 따로 정해야 한다.

　그래서 계정, 집, 가족과 라즈베리파이의 연결을 나눠서 만들었다.

　**앞에서 준비할 것:** 상태 확인에서 `ready`와 `ok`로 응답하는 A50 서버, 본인 Google 계정.

| 구분 | 확인할 내용 |
| --- | --- |
| Google 로그인 | 지금 요청한 사람이 누구인가 |
| 가족 권한 | 그 사람이 이 집에 참여해 있는가 |
| Pi 연결 키 | 이 기록을 보낸 라즈베리파이가 어느 집 소속인가 |

## 내 Firebase 프로젝트를 만들었다

---

　Firebase는 Google 로그인과 휴대폰 알림을 준비할 때 사용하는 서비스다. 기존 프로젝트가 없어서 새로 만들었다.

　Firebase Console(`https://console.firebase.google.com/`)에 로그인하고 프로젝트 만들기를 선택한다. 표시 이름은 알아보기 쉽게 정하고, **프로젝트 ID**는 프로젝트 설정에서 따로 적어두자. 이후 서버와 앱에 같은 값을 넣는다.

　나는 Spark 요금제로 시작했고 Google 애널리틱스는 연결하지 않았다. 여기서는 Google 로그인과 FCM 알림에 필요한 범위부터 준비한다. 가입 화면에서 현재 요금과 한도를 확인하고, 별도 필요 없이 유료 결제나 무료 체험을 연결하지는 말자.

　본인 프로젝트를 만들면 된다. 내 프로젝트 ID나 계정을 복사해 쓰는 과정은 없다.

## Google 로그인을 켰다

---

　Firebase Console에서 Authentication → 시작하기 → 로그인 방법 → Google로 들어간다. 사용 설정을 켜고 앱에 표시할 이름과 지원 이메일을 정한 뒤 저장한다.

　지원 이메일은 로그인 화면에 보일 수 있다. 어떤 주소를 쓸지 먼저 생각하자.

　이 단계에서는 로그인 제공자만 켠다. Android 앱과 서명을 등록하는 일은 가족 앱 제작 글에서 이어서 한다.

## 서버에도 같은 프로젝트를 알려줬다

---

　**PC PowerShell**에서 본인 프로젝트 ID를 넣는다.

```powershell
$firebaseProject = '본인의-Firebase-프로젝트-ID'
.venv/Scripts/python.exe scripts/android/configure_a50_firebase.py --project-id $firebaseProject
.venv/Scripts/python.exe scripts/android/verify_a50_households.py
```

　첫 명령은 A50의 비공개 설정을 저장하고 중앙 서버를 다시 시작한다. SSH 연결은 그대로 둔다. 두 번째는 로그인하지 않은 요청이나 가짜 로그인 정보가 거절되는지도 확인한다.

　여기에 넣는 값은 프로젝트 ID다. Google 비밀번호나 알림 전송용 개인 키를 넣는 칸이 아니다.

## 가족은 초대를 받아 들어오게 했다

---

　앱에서 집을 만든 사람이 그 집의 소유자가 된다. 소유자는 가족의 Google 이메일을 지정해 초대 코드를 만든다. 가족은 자신의 계정으로 로그인하고 코드를 입력한다.

　코드만 알면 아무나 들어가는 방식으로 만들지는 않았다. 초대받은 이메일과 로그인한 이메일이 같아야 한다.

| 상황 | 처리 |
| --- | --- |
| 초대한 이메일로 로그인 | 유효한 초대 코드로 참여 가능 |
| 다른 이메일로 로그인 | 같은 코드를 받아도 참여 거절 |
| 이미 사용한 코드 | 다시 사용 불가 |
| 만든 지 24시간이 지난 코드 | 만료되어 사용 불가 |
| 집에서 제외된 가족 | 해당 집의 정보 조회 불가 |

　라즈베리파이에도 각각 다른 연결 키를 준다. 서버는 그 키로 소속 집을 확인한다. Pi가 보내는 집 번호만 믿고 받아들이지는 않는다.

　집 정보를 읽을 때마다 가족 목록을 확인하는 실제 코드는 아래처럼 작성했다. 전체 서버 소스의 일부이며, 이것만 따로 실행하는 코드는 아니다.

```python
@staticmethod
def access(conn, home: str, user: str, *, owner=False):
    row = conn.execute('SELECT m.role FROM memberships m JOIN users u ON u.id=m.user_id '
                       'JOIN homes h ON h.id=m.home_id '
                       'WHERE m.home_id=? AND m.user_id=? AND m.active=1 AND u.active=1 AND h.active=1',
                       (home, user)).fetchone()
    if not row:
        raise APIError('not_found', 404)
    if owner and row['role'] != 'owner':
        raise APIError('owner_required', 403)
    return row['role']
```

　현재 활동 중인 계정과 집, 그 집의 가족 관계가 함께 있어야 한다. 없으면 조회를 거절하고, 소유자 작업은 `owner` 권한까지 확인한다. 앱 화면에서 버튼을 숨기는 것만으로 권한을 대신하지 않았다.

　가족 초대는 앱을 만든 뒤 써보기로 했다. Pi에도 나중에 이 집의 연결 키를 등록한다.

## 남의 집 요청이 거절되는지 코드로 확인했다

---

　화면에 우리 집이 보이는 것만 확인하면 권한 확인이 빠진 곳을 놓칠 수 있다. 그래서 다른 집 조회, 잘못된 로그인 정보, 초대 재사용과 가족 제외 뒤 접근을 코드로 확인했다.

　**PC PowerShell**에서 실행한다. 시험용 계정과 임시 기록 파일을 사용하며 실제 가족이나 집을 만드는 명령은 아니다.

```powershell
.venv/Scripts/python.exe -m pytest tests/test_central_households.py tests/test_central_push_api.py -q
```

　끝에 `passed`가 나오면 해당 코드 확인을 통과한 것이다. 여기까지는 시험용 계정으로 확인했다. 서로 다른 가족 계정의 실제 휴대폰 두 대로 전 과정을 해본 결과는 아직 아니다.

　한 가지 더 구분해둘 것이 있다. 현재 코드는 새로운 Google 사용자가 **자기 빈 집을 만드는 것**은 허용한다. 그 사람이 이미 있는 다른 집에 들어갈 수 있다는 뜻은 아니다.

　판매용으로 바꾼다면 누가 새로 가입할 수 있는지도 정해야 한다. 이번 개인 프로젝트에서는 본인과 가족의 계정으로 먼저 사용해보기로 했다.

　**여기까지 확인할 것:** Firebase에서 Google 로그인이 켜졌고, A50 서버에도 같은 프로젝트 ID가 저장됐다.

　서버가 사람과 집을 구분할 준비는 됐다. 다음에는 실제 휴대폰에 설치할 앱을 만들어보자.
