# 가족 앱에서 집이 보이지 않을 때

## 서버를 다시 켠 뒤 주소 오류가 뜨는 경우

　2026-10-11에는 서버가 다시 켜진 뒤 앱에서 집이 보이지 않았고 ‘서버 연결·주소 오류’가 나타났다. A50의 저장 파일을 읽어 현재 사용하는 집과 가족 등록이 남아 있는 것을 확인했다. 현재 HTTPS 주소로 서버도 정상 응답했다. 사용자가 현재 주소를 앱에 저장하고 같은 Google 계정으로 로그인하자 기존 집이 다시 보였다고 알려줬다.

　현재 쓰는 Cloudflare Quick Tunnel은 임시 연결이다. 연결 프로그램이 다시 시작되면 HTTPS 주소가 바뀔 수 있다. 앱이 이전 주소로 연결하면 서버의 집 목록을 읽지 못한다. 주소 오류는 집 삭제와 다르므로 새 집을 만들거나 앱·서버 데이터를 지우기 전에 연결부터 확인한다.

1. 앱의 오류 문구를 확인한다. 연결 실패인지, 서버에 연결한 뒤 정말 빈 목록을 받았는지 구분한다.
2. 서버 관리 PC에서 `server` 폴더를 열고 아래 읽기 전용 도구를 실행한다. 자신의 SSH 설정이 먼저 준비돼 있어야 한다.

```powershell
.venv/Scripts/python.exe scripts/android/verify_a50_tunnel.py
```

3. `HEALTH_READY=200 DATABASE=ok`와 `EXTERNAL_ROUTE=PASS`가 나오는지 확인한다. 도구는 현재 주소를 Git에서 제외한 `.deploy/a50/tunnel-endpoint.json`에 저장한다. 공개 캡처에는 주소를 넣지 않는다.
4. 파일의 현재 주소를 개인적으로 확인하고 앱의 **연결 설정**에 저장한다. 주소를 바꾸면 기존 로그인은 풀리므로 원래 집에 참여한 것과 같은 Google 계정으로 다시 로그인한다.
5. 기존 집이 보이는지 확인한다. 계속 실패하면 오류 문구와 현재 서버 상태를 확인하고 데이터 삭제나 새 집 생성으로 우회하지 않는다.

　0.4.0은 서버의 답을 받기 전부터 ‘아직 연결된 집이 없어요’를 표시하고 연결 실패는 잠깐 뜨는 안내로만 보여줬다. 0.4.1은 불러오는 중·연결 실패·실제로 빈 목록인 상태를 나누고 연결 실패 안내를 화면에 남긴다. 같은 로그인 상태에서 읽어 둔 목록이 있으면 ‘마지막으로 확인한 집’으로 표시한다. 앱을 다시 켠 뒤까지 보관하는 목록은 아니며 계정이나 서버가 바뀌면 지운다.

　이번 변경은 주소를 자동으로 고정하거나 새 주소를 자동 배포하는 기능이 아니다. 재시작 후에도 주소를 바꾸지 않으려면 고정 주소를 별도로 준비해야 한다. 새로운 공개 연결이나 인증 구조는 이번에 추가하지 않았다.

## 이번에 확인한 범위

- 기존 운영 집·가족 등록 보존과 저장 파일 정상 상태.
- 현재 HTTPS 상태 확인 200, 인증 없는 요청과 가짜 인증 요청 거절 401.
- 사용자 휴대폰에서 현재 주소를 저장한 뒤 기존 집이 다시 보임.
- 0.4.1 단위 확인 8개 통과, 개발용·배포용 APK 생성, 기존 앱과 같은 서명·배포용 HTTPS 정책·시험 자료 제외 확인.
- A50 화면 연결은 실패해 0.4.1의 실기기 화면 확인은 남았다. APK 설치·알림 수신까지 성공했다고 기록하지 않았다.

　실제 실행 기록은 `docs/assets/terminal/149-a50-tunnel-public-verification.txt`, `150-a50-missing-homes-diagnosis.txt`, `151-a50-family-apk-build.txt`, `152-a50-family-apk-verification.txt`에 남겼다.

## 가족 앱 설치 도구가 개발용 APK를 바로 설치하지 않는 경우

　2026-10-15 보안 검토에서 `scripts/android/install_test_family_app.py --production-only`를 `--release` 없이 실행하면 개발용(debuggable) APK가 같은 서명·버전 코드로 로그인한 배포용 앱을 덮어쓰고, 그 뒤 `run-as`로 앱의 저장 데이터를 읽을 수 있게 되는 점을 확인했다. 그래서 기본값을 배포용 `family-release.apk`로 바꿨다. 기존 안내의 `--release`는 그대로 받지만 아무것도 바꾸지 않는다. 개발용 빌드를 설치하려면 `--debug`를 명시해야 하고 경고 한 줄이 나온다. `scripts/android/verify_family_apk.py`는 배포용 APK에 `application-debuggable`이 있으면 실패하고, `scripts/android/update_a50_family_app.py`는 debuggable APK를 설치하지 않는다.

　같은 검토에서 함께 바꾼 것: `uiautomator dump` 결과를 휴대폰 `/data/local/tmp`에 남기지 않고 같은 명령 안에서 읽은 뒤 지운다. 빌드 복사본에서는 `private-build.json`, `local.properties`, 시험용 fixture 파일과 `app/build/intermediates`를 빌드가 끝나면 지우고, 오래된 복사본은 최신 2개만 남긴다. 공개 캡처 기록은 PC 계정 이름, IPv6·MAC 주소, `*.ts.net`·`*.trycloudflare.com` 주소, 페어링 코드도 가린다. 저장한 SSH 사용자 이름이 `-`로 시작하면 ssh 옵션으로 읽힐 수 있어 거부한다. 관리 앱 0.4.1은 화면을 여는 것만으로 복구를 실행하지 않는다. 0.4.1은 아직 실기기에 설치하지 않았다.
